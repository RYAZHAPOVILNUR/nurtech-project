# Страница «Эпики»

Связан с [01-scope.md](01-scope.md) и [02-scenarios-and-permissions.md](02-scenarios-and-permissions.md). Макеты: [wireframes/epic/](wireframes/epic/) (`list.svg`, `dialog-create.svg`, `states.svg`; карточка эпика `card.svg` ещё не доработана).

## 1. Назначение и доступ
Список всех эпиков проекта с прогрессом, сроками и суммами времени. Отсюда создают эпики и открывают их карточки.
- Маршрут: `/p/PROJ/epics`. Открывается из переключателя видов (раздел «Списки»).
- Просмотр: все роли проекта (`task-view`). Кнопка «+ Эпик»: `task-create` (viewer её не видит).

## 2. Раскладка
- Панель: переключатель видов, поиск по названию и ключу, переключатель «Открытые / Закрытые / Все» (по умолчанию «Открытые»), фильтр по assignee (несколько значений), кнопка «+ Эпик».
- Таблица, колонки: Ключ · Название · Прогресс · Статус · К дате · Assignee · Оценка · Затрачено.
- Под таблицей: «Показано N из M эпиков».
- Раскрытие строки показывает дочерние задачи (ключ, название, статус, assignee) и ссылку «Все задачи эпика →» (вид «Все задачи» с фильтром по эпику).
- Клик по названию открывает карточку эпика в боковой панели.

## 3. Поведение
**Загрузка данных.** Один запрос возвращает все неархивные эпики проекта (потолок 500). Пагинации и бесконечной ленты нет: фильтры и сортировка работают на клиенте. Если эпиков больше потолка, под таблицей сообщение «Показаны первые 500 эпиков, уточните поиск». Дочерние задачи подгружаются при раскрытии строки (до 50; если их больше, показывается «показано N из M» и ссылка «Все задачи эпика →»). Данные обновляются при возврате на вкладку.

**Фильтры.** Условия соединяются по И. «Открытые» = статус не из категории done; «Закрытые» = из категории done. Состояние фильтров и сортировки хранится в URL: `/p/PROJ/epics?status=open&assignee=12,15&q=...&sort=dueDate:asc`.

**Сортировка** (только где есть практическая польза): Ключ (по умолчанию, новые сверху), Прогресс, К дате (ближайшие сроки сверху). Клик меняет направление, третий клик возвращает порядок по умолчанию. Эпики без срока всегда внизу.

**Строка.**
- Прогресс: полоса и «закрыто/всего» по прямым дочерним Task и Bug (подзадачи не считаются). У эпика без задач вместо полосы текст «Нет задач».
- Статус: цветная метка статуса эпика. Статус эпика ставится вручную и не зависит от задач.
- К дате: если срока нет, «—»; красным выделяется срок, который прошёл, у незакрытого эпика.
- Assignee: аватар и имя; если не назначен, «не назначен».
- Закрытые эпики (категория done) отображаются приглушённо.
- Оценка и Затрачено: суммы в формате `2h 30m`; если данных нет, «—».

**Подсказки у заголовков «Оценка» и «Затрачено» (обязательны).** Текст подсказки нужно добавить в задачу на фронт:
- «Оценка»: «Сумма оценок задач эпика. Если у задачи есть подзадачи, учитываются оценки подзадач, а собственная оценка задачи не учитывается.»
- «Затрачено»: «Сумма времени, списанного по всем задачам и подзадачам эпика.»

**Создание эпика.** Кнопка «+ Эпик» открывает диалог «Новый эпик»: Название (обязательное, помечено звёздочкой), К дате, Assignee. Кнопка «Создать» неактивна, пока название пустое; при пустом названии после попытки отправки показывается ошибка «Введите название эпика». Во время отправки поверх диалога показывается индикатор загрузки, текст кнопки не меняется. После успеха диалог закрывается, эпик появляется в таблице и открывается его карточка. При ошибке сервера диалог остаётся открытым, показывается сообщение об ошибке.

**Закрытие эпика** выполняется в карточке эпика (не в таблице); подсказка о том, что все задачи закрыты, проектируется вместе с карточкой.

## 4. Состояния страницы
Загрузка (индикатор поверх таблицы); в проекте нет эпиков (текст «Эпиков пока нет. Эпик объединяет задачи одной цели», кнопка «+ Эпик» только при `task-create`); фильтры ничего не нашли («Ничего не найдено», кнопка «Сбросить фильтры»); ошибка загрузки («Не удалось загрузить эпики», кнопка «Повторить»); ошибка раскрытия строки («Не удалось загрузить задачи эпика», «Повторить»); достигнут потолок 500. Подробно на `wireframes/epic/states.svg`.

## 5. API (черновик)
- `GET /projects/:id/epics` → `[{ id, key, title, status{id,name,color,category}, assignee{id,name}|null, dueDate|null, childrenTotal, childrenDone, estimateMinutes|null, spentMinutes|null, updatedAt }]`.
- `GET /epics/:id/tasks` → `[{ id, key, title, type, status, assignee }]` (до 50, с общим количеством).
- `POST /tasks` (type=Epic; title, dueDate, assigneeId).
- `GET /projects/:id/members?search=` для фильтра и диалога.
- Суммы: оценка эпика = сумма оценок задач и подзадач; если у задачи есть подзадачи, берутся оценки подзадач, а оценка задачи игнорируется. Затрачено = сумма всех worklog по эпику и дочерним, включая подзадачи.

## 6. Сценарии
- **E1 Просмотреть эпики.** Открыть вид «Эпики» → таблица открытых эпиков, сортировка по ключу (новые сверху).
- **E2 Отфильтровать.** Выбрать «Закрытые» / «Все», выбрать assignee, ввести текст → таблица обновляется, адрес содержит параметры.
- **E3 Отсортировать.** Клик по «К дате» → сроки по возрастанию; повторный клик → по убыванию; третий → по умолчанию.
- **E4 Раскрыть эпик.** Клик по строке → список дочерних задач; «Все задачи эпика →» ведёт в «Все задачи» с фильтром.
- **E5 Создать эпик.** «+ Эпик» → ввести название (К дате и Assignee по желанию) → «Создать» → открывается карточка эпика.
- **E6 Открыть карточку.** Клик по названию → боковая панель (карточка эпика).
- Ошибки: пустое название, сбой запроса, потеря прав (403), нет эпиков.

## 7. Оценка трудозатрат фронта: ≈ 24–28 ч
Таблица, колонки, сортировка 6; фильтры и синхронизация с URL 8; раскрытие с подгрузкой 5; диалог создания 5; состояния 4; права и вёрстка 2–4.

## 8. Открытые вопросы
- Подсказка «все задачи закрыты, закрыть эпик?» и кнопка закрытия: проработать в карточке эпика.
- Как показывать эпик, у которого дочерние задачи есть, но ни одна не Task/Bug (только подзадачи): считаем прогресс «Нет задач».
