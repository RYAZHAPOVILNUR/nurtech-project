# Общие правила интерфейса

Правила, общие для всех страниц. Нужны, чтобы ученики не принимали решения заново на каждом экране. Связан с [01-scope.md](01-scope.md). Решения по спорным правилам: Q-19, Q-20, Q-21 ([decisions.md](decisions.md)). Ошибки API — раздел 8, markdown — раздел 9.

У каждого правила, где это возможно, указано, как его проверить: **axe** (расширение или `@axe-core/playwright` на странице в нужном состоянии), **Lighthouse** (категория «Accessibility», порог 90 и выше), **ревью** (проверяет ревьюер по чек-листу из [15-backlog.md](15-backlog.md)) или **скрипт глоссария** (раздел 1).

## 1. Язык и термины
- Интерфейс только на русском. Подписи полей: «Исполнитель», «Ревьюер», «Направление», «К дате», «Оценка», «Затрачено». Названия статусов — данные проекта и могут быть любыми.
- **Исключения (имена собственные, пишутся по-английски):**
  - типы задач: Task, Bug, Subtask;
  - приоритеты: Low, Medium, High, Critical;
  - роли проекта: Owner, Admin, Member, Viewer.
  
  Область: подписи значений в списках, фильтрах, таблицах, бейджах и на кнопках выбора. Во фразах и пояснениях те же понятия пишутся по-русски: «владелец проекта», «администратор проекта», «исполнитель», «ревьюер» («Прежний владелец станет администратором проекта», «Попросите владельца проекта»). Других английских слов в интерфейсе нет. Проверка: ревью; в шаблонах нет латиницы вне исключений, `@логинов`, ключей задач (`PROJ-123`) и названий из данных.
- **Типы связей — по-русски:** «Блокирует», «Заблокирована». Английские `blocks` / `blocked_by` остаются только в API и коде.
- **Роли.** Глобальная роль — всегда «системный администратор» (слово «админ» без уточнения не пишем). Роль проекта — Admin как имя роли, в тексте «администратор проекта».
- **Архив и активация.** Задачу (и, после релиза, проект) возвращают из архива кнопкой «Восстановить»; пользователя после деактивации — кнопкой «Активировать» (в API `restore` и `activate`). Слова «Вернуть» и «Вернуть из архива» в интерфейсе не используются.
- Сущность называется «задача»; «карточка задачи» — окно подробного просмотра; на доске элемент колонки — «карточка». Кнопки добавления: «+ Задача», «+ Подзадача», «+ Связь», «+ Ссылка», «+ Тег», «+ Участники».
- **Общее сообщение приложения** (тост) — всплывающее сообщение об ошибке или результате действия («Не удалось …», с кнопкой «Повторить», где повтор уместен). В остальных документах оно называется «общее сообщение приложения», слово «тост» — только здесь.

**Глоссарий** (русское слово в документах и интерфейсе → идентификатор в API; идентификаторы пишутся в обратных кавычках):

| Понятие | По-русски | В API и коде |
|---|---|---|
| Исполнитель | исполнитель | `assignee`, `assigneeId` |
| Ревьюер | ревьюер | `reviewer`, `reviewerId` |
| Автор задачи | автор | `reporterId` |
| Направление | направление (маршрут и ключ права — `subsystems`, `subsystem-manage`) | `subsystem` |
| Подписки | подписка, подписчики | `watch`, `watching` |
| Затраченное время | списание времени, «Затрачено» | `worklog`, `spentMinutes` |
| Владелец проекта | владелец (роль — Owner) | `owner` |
| Глобальная роль | системный администратор | `isSystemAdmin` |
| Серверная часть | бэкенд | — |
| Бэклог | бэклог | — |
| Срок жизни ссылки или сессии | срок действия (не «срок» — так называется поле «К дате») | — |
| Повторная выдача доступа | «Новая ссылка» — повторная выдача ссылки-приглашения; не путать с «+ Ссылка» в задаче | `reissue`, `user-reissue-access` |
| Копирование адреса | «Копировать ссылку» (не «Скопировать») | — |

Проверка глоссария (ревью): в текстах 01–15 и README вне обратных кавычек и блоков кода нет `assignee`, `reviewer`, `watchers` и написания `бекенд` (правильно — «бэкенд»).

## 2. Формы и диалоги
- **Кнопка отправки всегда активна** (отключённая кнопка не объясняет причину); ошибки показываются под полем при нажатии, фокус переходит на первое поле с ошибкой. Проверка: на пустой форме кнопка не имеет `disabled`, после нажатия у первого невалидного поля `aria-invalid="true"` и фокус.
- **Исключение — формы правки существующих данных** (профиль, «Общие» настройки проекта): «Сохранить» неактивна, пока нет изменений, и становится активной при первом изменении. К исключению не относятся поля добавления («Новое направление» с «Добавить», «Добавить» в окне ссылки или тега, формы создания): там кнопка всегда активна, пустое поле даёт ошибку под полем. Проверка: ревью по списку форм правки (профиль, «Общие»); на остальных формах `disabled` нет.
- Обязательное поле отмечено «*»; подписи «(необязательно)» не нужны.
- **Несохранённые изменения — одна схема из двух кнопок:** «Остаться» (возврат к редактированию) и «Закрыть без сохранения». Вопрос задаётся при закрытии (крестик, Esc, «Отмена», уход со страницы) заполненной формы создания и описания карточки с изменениями; пустая или неизменённая форма закрывается сразу. Третьей кнопки «Сохранить» в такой подтверждающей форме нет: сохранить можно только явной кнопкой самой формы. Проверка: приёмка закрытия диалога создания ([05](05-create-task-dialog.md)) и редактора описания ([04](04-task-card.md)).
- **Подтверждение удаления.** Любое удаление записи подтверждается окном с описанием последствий: комментарий, списание времени, связь, ссылка, статус, тег и направление в справочнике, доска, участник проекта. Заголовок окна — «Удалить …?», кнопки «Отмена» и «Удалить» (опасная). Исключение: снятие тега с задачи (✕ на чипе) — это не удаление записи, тег остаётся в проекте; подтверждения нет. Проверка: приёмка по сценариям страниц; ревью — у каждой кнопки с 🗑 или «Удалить» есть окно.
- **Разрушающие действия** (удаление, архивация, деактивация, отвязка, выдача новой ссылки) — подтверждение с описанием последствий и **«опасная» кнопка**: отдельный вид кнопки Taiga UI (`tuiButton` с негативным/destructive-видом — точное имя `appearance` проверить в установленной версии), цвет не основной синий. Действие в строке таблицы, которое открывает подтверждение («Деактивировать», «Новая ссылка»), — обычная текстовая ссылка; «опасной» делается кнопка в окне подтверждения. Кнопка «Отмена» — вторичная. Проверка: ревью; на страницах 08, 09, 10 и в карточке нет основной синей кнопки с глаголом разрушающего действия.
- Кнопки диалога одной ширины (по самой длинной); во время отправки поверх диалога индикатор, текст кнопки не меняется. Проверка: ревью, `getBoundingClientRect().width` кнопок диалога равны.
- Правки полей карточки сохраняются автоматически; ошибка сохранения откатывает значение и показывает общее сообщение.
- Если у проекта нет направлений, поле «Направление» в карточке и диалоге создания, колонка в списке и фильтр на «Все задачи» и досках не показываются (так в шаблоне «Simple», пока значений нет).

## 3. Состояния страниц
- У каждой страницы с данными есть **три состояния, и у каждого свой кадр на макете**: загрузка (индикатор поверх контента), пусто (с подсказкой, что делать), «ничего не найдено» (с кнопкой «Сбросить»). Это относится и к настройкам, участникам, администрированию. Общее правило не заменяет кадры (Q-20). Правило — для страниц со списками и таблицами; состояния без отдельного кадра (загрузка профиля, «Показать ещё» в комментариях, загрузка кандидатов в окне добавления участников, ошибка занятого ключа проекта) описаны в тексте страниц.
- Формулировка кнопки сброса поиска и фильтров везде одна — «Сбросить» (не «Сбросить фильтры»).
- Ошибки сети и сервера показываются общим сообщением приложения; отдельных экранов ошибок нет. Сообщение двух видов: с кнопкой «Повторить» (загрузка, автосохранение) и без неё («Не удалось …», где повтор бессмыслен). Пример для проверки — кадр в `navigation/shell.svg`. Сообщение исчезает через 8 секунд или по ✕; ошибка валидации сообщением не показывается. Какой текст показывать на каком ответе API — раздел 8.
- **Проект в архиве** (действует вместе с архивацией проекта, которая вынесена за первую версию, Q-23): на всех страницах проекта под верхней панелью баннер «Проект в архиве · только чтение». Всё, кроме просмотра, недоступно: нет перетаскивания, «+ Задача», правки полей и комментариев; настройки проекта видит только owner. Возврат из архива делает системный администратор в администрировании проектов, в баннере кнопки нет. Проверка: ревью и приёмка после включения функции.
- **Деактивированный пользователь** (как исполнитель, ревьюер, автор, участник): подпись «(деактивирован)» рядом с именем; цвет не единственный сигнал. Имя и подпись — вторичный текст `#6c7088` (4,87 на белом) **без `opacity`**; аватар — серый фон с тёмными инициалами (≥ 4,5). В выпадающих списках исполнителя и ревьюера деактивированных нет; уже назначенный деактивированный показан серым с подписью, его можно только снять. Проверка: ревью, axe; в таблице участников и в полях задачи есть текст «(деактивирован)».
- **Приглашённый** (после «Новой ссылки» человек получает статус «Приглашён», Q-32 а) выглядит как обычный участник: без серого цвета и без подписи; «(деактивирован)» только у деактивированных (`active = false`). Назначать исполнителем и ревьюером можно любого участника, кроме деактивированного. Проверка: ревью.

## 4. Клики и клавиатура
- Одинарный клик по карточке доски или строке списка выделяет её; открывают задачу двойной клик, Enter у выделенной и одинарный клик по ключу (ключ — ссылка).
- Esc закрывает панель, окно и выпадающие списки; в формах с несохранёнными данными сначала задаётся вопрос по схеме из раздела 2 («Остаться» / «Закрыть без сохранения»).
- Перетаскивание карточек не имеет клавиатурной альтернативы; её заменяет смена статуса в карточке задачи.

## 5. Доступность и читаемость
- Каждая иконка-кнопка имеет подсказку (`tuiHint`) и доступное имя (`aria-label`) по таблице в разделе 7. Проверка: axe, правила `button-name` и `aria-label`; ревью таблицы.
- Цвет не единственный сигнал: статус — точка и текст, приоритет — цвет и буква, просроченный срок — красный цвет и иконка часов, блокировка — ⛔ и текст, деактивация — серый и «(деактивирован)», непрочитанное уведомление — фон и точка. Проверка: ревью.
- **Размер текста.** В реализации любой текст не мельче 12 px. Размеры 8–11 px на макетах (инициалы аватаров, буквы типа и приоритета, подписи полей, ошибки, подсказки, @логины, чипы тегов, даты) — условность компактности макета, в реализацию их не переносят. Проверка: тест обходит текстовые узлы страницы и проверяет `getComputedStyle(...).fontSize ≥ 12px`; для аватаров и бейджей — ревью.
- **Контраст.** Контраст текста не ниже 4,5:1 (axe, правило `color-contrast`; Lighthouse). Конкретные роли:
  - **Бейдж приоритета** (квадрат с буквой L/M/H/C) — тёмная буква `#1b1f3b` на цвете приоритета (контраст 7,1–8,2), не белая. Проверка: axe и ревью.
  - **Инициалы аватара** — тёмный текст на светлом фоне (`#1b1f3b` на `#9aa7d8` = 6,81) либо автоцвет `tuiAvatar` с проверенной парой (≥ 4,5). Белый текст на `#9aa7d8` (2,36) не используется.
  - **Буква типа** (T/B) на подложке — цвет темнее макетного (например `#3f5bc4` на `#e0e5f7` = 4,77) либо плотнее подложка; ⛔ «заблокировано» — `#d03a26` на подложке, итог ≥ 4,5.
  - **Негативный текст** (ошибки валидации, просроченный срок, «Не удалось …») — токен негативного текста Taiga UI, а не цвет заливки `#f45d48` / `#e4513a`; контраст токена на белом и на `#f9f9fc` не ниже 4,5 (например `#d03a26` = 4,87). Ошибка на цветной плашке — `tuiNotification` без своих цветов. Проверка: axe на странице с ошибкой валидации и с просроченным сроком.
  - **Серый текст — две роли.** Плейсхолдер поля — токен плейсхолдера Taiga UI (контраст проверить по axe; серый `#9a9db0` не применять). Вторичный текст — пустые значения («—», «не назначен»), подсказки («Перетащите сюда», «Добавьте описание»), поля только для чтения (логин, ключ проекта), относительное время: `#6c7088` (4,87 на белом). Проверка: ревью и axe.
  - Штатные токены Taiga (неактивный сегмент, счётчик колонки, «+N» тегов, панель форматирования) на штатных подложках не переопределяются; контраст проверяется axe и Lighthouse, цвета макета при расхождении не копируются. Ссылки и кнопки-текст (`tuiLink`) на подложках и выделенных строках — штатный токен Taiga UI, проверяется axe; акцентный `#526ed3` макета (4,07–4,41 на подложках) не копируется.
- На макетах эмодзи (🔍 ⚙ 🗑 🔔 ✈ 📅) обозначают иконки: в реализации используются иконки Taiga UI.

## 6. Форматы
- Время: `2h 30m` (часы и минуты). Даты: «3 ноя», в формах «дд.мм.гггг». Относительное время: «5 минут назад», «вчера».
- **Даты без времени** (`dueDate` задачи, `date` списания) — строки `YYYY-MM-DD`; в `Date` не преобразуются: `new Date('2026-11-03')` — это полночь UTC, и западнее UTC покажет предыдущий день. В формах используется `TuiDay` (проверить API в установленной версии Taiga UI), в запрос уходит строка `YYYY-MM-DD`. Моменты (`createdAt`, `updatedAt`, время уведомления) — `Date`, показ в часовом поясе браузера. «Сегодня» для даты списания — локальная дата пользователя. Просрочку определяет бэкенд (`isOverdue` в ответе), на фронте она не пересчитывается.
- Приоритет: Low / Medium / High / Critical (цвет и буква L/M/H/C, исключение из раздела 1).
- Срок действия ссылки-приглашения и сессии пишется «срок действия», чтобы не путать с полем «К дате».

## 7. Иконки: назначение и доступное имя
Одно значение — одна иконка. **🗑 — удаление записи** (строка таблицы, комментарий, списание, участник), **✕ — закрыть окно или панель, снять чип тега, закрыть общее сообщение**. Удаление связи и ссылки в списке — тоже 🗑.

| Иконка | Где | Доступное имя и подсказка |
|---|---|---|
| ⚙ | верхняя панель | «Меню проекта» |
| ✕ | окно, панель, общее сообщение; чип тега | «Закрыть»; «Убрать тег» |
| 🗑 | таблица настроек, участник, комментарий, списание, связь, ссылка | «Удалить»; у участника — «Удалить из проекта» |
| ✎ | строка таблицы, комментарий | «Изменить» |
| ⠿ | карточка доски | «Перетащить» |
| ▸ | строка с подзадачами | «Показать подзадачи» / «Скрыть подзадачи» (`aria-expanded`) |
| 👁 | поле пароля | «Показать пароль» / «Скрыть пароль» (`aria-pressed`) |
| ☆ / ★ | шапка карточки | «Подписаться» / «Отписаться» (`aria-pressed`) |
| ⧉ | шапка карточки, рядом с ключом | «Копировать ссылку» |
| ⎇ | блок «Ссылки» (перед названием ссылки) | декоративная, `aria-hidden`, подсказки нет |
| ⋯ | шапка карточки | «Действия» |
| 🔒 | поле только для чтения | «Только для чтения» |
| ⓘ | «по подзадачам» | текст из [04](04-task-card.md), раздел 4 («Сумма оценок подзадач»; «Сумма времени, затраченного на подзадачи») |
| 🔔 | верхняя панель | «Уведомления, непрочитанных: N» |

Проверка: axe (`button-name`), ревью таблицы при добавлении иконки.

## 8. Ошибки API и реакция фронта
Любая ошибка 4xx и 5xx приходит телом `ErrorResponse`: `error.code` из перечня, `error.message` (по-русски), для 422 и `name_taken` — `fields` (ключ — имя поля запроса, значение — `FieldErrorReason`), иногда `details` ([backend/00](backend/00-conventions.md), раздел 3). Решение принимает **один перехватчик**, страницы добавляют только свои тексты для перечисленных у них кодов.

| Ответ | Реакция фронта |
|---|---|
| Нет сети, таймаут, 5xx (`internal_error`) | Общее сообщение «Не удалось выполнить действие. Повторите попытку». Изменение не применяется: оптимистичное откатывается, поле автосохранения возвращается к прежнему значению |
| 400 `bad_request` | Это ошибка фронта: то же общее сообщение, запрос пишется в консоль |
| 401 `unauthenticated` | Сбросить состояние, перейти на `/login` с адресом возврата ([10](10-account-and-admin.md), раздел 2) |
| 401 `invalid_credentials` | Под формой входа — `message` бэкенда |
| 403 `forbidden` | Перезапросить `GET /auth/me` и права проекта (`GET /projects/:id/me`), обновить видимость кнопок, показать «Недостаточно прав» |
| 403 `password_change_required` | Перейти на `/change-password` |
| 403 `account_deactivated` | Выйти на `/login` с сообщением «Аккаунт деактивирован. Обратитесь к системному администратору.» |
| 404 `not_found` на странице ресурса (задача, доска, проект) | Экран «Не найдено или нет доступа» со ссылкой на проект или список |
| 404 при действии в списке | Общее сообщение и перезапрос списка |
| 404 `invitation_invalid` | Экран «Ссылка недействительна» |
| 409, общий случай | `message` бэкенда рядом с действием: общее сообщение или текст в окне |
| 409 `stale_position` | Откатить карточку и перезапросить доску (без сообщения) |
| 409 `name_taken` | Текст под полем; у тега при создании на лету — взять `details.tag` и поставить его без сообщения |
| 409 `move_to_required` | Открыть выбор статуса или направления, куда перенести задачи |
| 409 `task_archived` | Перечитать задачу и показать её в режиме архива |
| 422 `validation_failed` | Тексты под полями по `fields` из словаря фронта; если поля нет на форме — `message` |
| 429 `too_many_attempts` | «Слишком много попыток. Повторите позже»; на форме входа — «Слишком много попыток. Попробуйте через N мин.», N — `Retry-After` в секундах, округлённый вверх до минуты |
| Неизвестный `code` | Реакция по HTTP-статусу из этой таблицы; показывается `message` бэкенда |

- **Словарь `FieldErrorReason → текст`** — один файл фронта; ключ — причина и форма (поле). Тексты берутся со страниц: `required` — «Заполните поле» (или текст страницы: «Укажите причину», «Введите название», «Выберите хотя бы одного человека»), `too_long` — «Не больше N символов», `taken` — «Такой логин уже занят» или «Такое название уже есть», `mismatch` — «Пароли не совпадают», `invalid` у пароля — «Не менее 8 символов, буква и цифра», у текущего пароля — «Неверный текущий пароль». Причины без записи в словаре и причины, которых фронт не знает (бэкенд добавил значение), показываются как «Проверьте значение»; запрос не повторяется.
- **Свой текст у кода** есть только там, где его задаёт страница (например, `last_owner`, `already_member`, `link_cycle`, `parent_archived`, `board_would_be_empty`). У остальных кодов показывается `message` бэкенда.
- **`details`** показывается в тексте окна: `last_owner.projects` — названия проектов, `board_would_be_empty.boards` — названия досок, `already_member.userIds` — по ним в списке выбора отмечаются те, кто уже в проекте.
- Ошибка валидации не показывается общим сообщением (раздел 3). Деактивированный человек, потеря прав и архив: 403 и 409 `task_archived` по таблице, несохранённый текст остаётся на экране.

## 9. Markdown и очистка разметки
- Описание задачи и комментарии рендерятся компонентом `ngx-markdown` (`<markdown [data]="…">`) со встроенным санитайзером Angular. Запрещены `bypassSecurityTrust*`, отключение санитайзера (`SecurityContext.NONE`) и вставка через `innerHTML` в обход компонента. Сырой HTML в тексте не исполняется.
- Правило одно для описания ([04](04-task-card.md), раздел 4) и для комментариев: markdown в комментарии пишет любая роль, включая viewer, а бэкенд текст не очищает ([backend/07](backend/07-comments-worklogs-watches.md), раздел 2). Ссылки открываются в новой вкладке с `rel="noopener noreferrer"`; схема `javascript:` не работает.
- Проверка: комментарий `<img src=x onerror=alert(1)>` и ссылка `[x](javascript:alert(1))` не выполняют код (в DOM нет обработчика `onerror`, у ссылки нет `javascript:`); то же в описании. Сценарий T7.7 в [04](04-task-card.md). Пакета `ngx-markdown` в `package.json` пока нет: добавляется задачей «Описание и просмотр markdown»; поведение санитайзера проверить в установленной версии.
