# Диалог создания задачи

Связан с [01-scope.md](01-scope.md), [02-scenarios-and-permissions.md](02-scenarios-and-permissions.md), [04-task-card.md](04-task-card.md). Макеты: [wireframes/create-task/dialog.svg](wireframes/create-task/dialog.svg) (Task по умолчанию, Subtask с ошибками, Bug с шаблоном, отправка).

## 1. Назначение и вызов
Единая форма создания Task, Bug и Subtask со всеми полями карточки (как в YouTrack). Права: `task-create`.
- Кнопка «+ Задача» на досках и в списке «Все задачи».
- Кнопка «+ Подзадача» в карточке задачи: тот же диалог с типом Subtask и подставленным родителем.
- Быстрого создания в колонке доски нет: любая задача создаётся только этим диалогом.

## 2. Раскладка
Диалог шириной около 900 px.
- Сверху переключатель типа: Task / Bug / Subtask (по умолчанию Task).
- Левая колонка: «Название *» и «Описание» (markdown с панелью форматирования и переключателем «Редактор / Просмотр»).
- Правая колонка (затенённая): Родитель * (только для Subtask), Статус, Приоритет, Исполнитель, Ревьюер, Направление, К дате, Оценка, Теги.
- Внизу «Отмена» и «Создать» одной ширины.
Связи, ссылки, комментарии и списание времени в диалоге не задаются, это блоки карточки.

## 3. Поведение
**Значения по умолчанию.** Тип Task. Статус: с доски — первая колонка текущей доски; из списка и из карточки — первый статус проекта. Приоритет Medium. Остальные поля пустые. Статусы с `requiresReason` (Cancelled, Blocked) в диалоге не предлагаются. С доски разработки задача попадает в To do (первая колонка доски) и минует планирование: это осознанное решение; задачу, которая должна пройти планирование, создают из списка или с доски планирования.

**Переключение типа.**
- Bug: если описание пустое, подставляется шаблон (Шаги воспроизведения / Ожидаемый результат / Фактический результат). Шаблон только подставляется: при возврате на Task или Subtask описание остаётся как есть, автоматически не убирается (Q-23, I-24).
- Subtask: появляется обязательное поле «Родитель» (поиск по ключу или названию среди неархивных Task и Bug проекта). Если диалог открыт из карточки, родитель уже выбран и его можно заменить.
- Task и Bug: поле «Родитель» скрыто, выбранное значение сбрасывается.

**Валидация.** «Название» обязательно; для Subtask обязателен «Родитель». Кнопка «Создать» всегда активна (отключённая кнопка не объясняет причину); при нажатии с незаполненными обязательными полями ошибка показывается красным под полем («Введите название», «Не больше 100 символов», «Выберите родительскую задачу»), фокус переходит на первое такое поле. Обязательность отмечена звёздочкой у названия поля.

**Поля.** Те же элементы управления, что в панели полей карточки: Статус и Приоритет (списки), Исполнитель и Ревьюер (поиск по участникам, в списке только не деактивированные; первый пункт «Я», пункт «Не назначен»; под полем «Исполнитель» ссылка «Назначить на меня», как в карточке), Направление (список проекта; если направлений нет, поле не показывается — [12](12-ui-rules.md), раздел 2), К дате (календарь), Оценка (`2h 30m`), Теги (кнопка «+ Тег», подсказки, создание нового тега по праву `tag-create`). Подзадача получает те же поля, что Task и Bug.

**Закрытие.** Если в форме введён текст (название или описание) или изменены поля, «Отмена», крестик и Esc сначала показывают подтверждение «Закрыть без сохранения?» (кнопки «Остаться» и «Закрыть без сохранения», схема из [12](12-ui-rules.md), раздел 2); пустая форма закрывается сразу. Клик вне диалога не закрывает его.

**Отправка.** Во время отправки поверх диалога показывается индикатор загрузки, текст кнопки не меняется. При ошибке сервера диалог остаётся открытым с введёнными данными, показывается общее сообщение приложения.

**После создания.** Диалог закрывается, созданная задача открывается в карточке (боковая панель поверх текущей страницы); список или доска обновляются и содержат новую задачу.

## 4. Права
`task-create` на весь диалог; `tag-create` для нового тега. Viewer кнопку «+ Задача» и «+ Подзадача» не видит.

## 5. API
Группы OpenAPI: Tasks (создание и поиск родителя), Members, Tags, Statuses, Subsystems (источники значений полей). Контракт — [backend/openapi/openapi.yaml](backend/openapi/openapi.yaml); ТЗ — [backend/04-tasks-core.md](backend/04-tasks-core.md).
- Создание — `POST /projects/:projectId/tasks`, ответ — созданная задача с ключом; подзадача создаётся с `parentId`.
- Выбор родителя использует `GET /projects/:projectId/tasks/search` с ограничением по типам `task,bug`.

## 6. Сценарии
- **C1 Создать Task:** ввести название, при желании заполнить поля, «Создать» → открывается карточка.
- **C2 Создать Bug:** переключить тип → появляется шаблон описания → заполнить, создать.
- **C3 Создать Subtask из карточки:** «+ Подзадача» → тип Subtask, родитель подставлен → название → создать.
- **C4 Ошибки валидации:** пустое название, не выбран родитель у Subtask.
- **C5 Отмена:** Esc, крестик, «Отмена»; для заполненной формы подтверждение «Закрыть без сохранения?».
- **C6 Ошибка сервера:** сообщение, данные сохраняются в форме.
Соответствие M3 из документа 02.

## 7. Оценка трудозатрат фронта: ≈ 33 ч
Оболочка диалога 6; форма и валидация 10; переключение типа и подстановка шаблона Bug 2; выбор родителя 6; поля (переиспользуются компоненты панели полей карточки) 5; отправка и открытие карточки 4. Без переиспользования компонентов карточки оценка выше (≈ 43 ч), поэтому порядок работы: сначала поля карточки, затем диалог. Снято упрощением Q-23: удаление нетронутого шаблона при смене типа −2 (I-24).

## 8. Открытые вопросы
- Нужны ли шаблоны описания для Task и настройка шаблона Bug на проекте (после релиза).

## Приёмка
Формат и сид — как в [04](04-task-card.md), раздел «Приёмка». Роль с правом `task-create` — `clara_member`; `eva_viewer` — viewer.

**C1 Создать Task** (M3)
- C1.1 Дано: `clara_member` на доске «Разработка». Действие: «+ Задача», ввести название, «Создать». Ожидаю: диалог закрылся, поверх доски открылась карточка с новым ключом; тип Task, приоритет Medium, статус — первая колонка доски (To do); на доске карточка в конце колонки.
- C1.2 Дано: диалог открыт из «Все задачи». Действие: заполнить все поля (исполнитель «Я», ревьюер, направление, срок, оценка `1h`, теги, описание), «Создать». Ожидаю: в карточке все значения; статус — первый статус проекта; список обновлён и содержит задачу.
- C1.3 Дано: в списке выбора статуса. Ожидаю: Cancelled и Blocked не предлагаются.
- C1.4 Дано: `eva_viewer`. Ожидаю: кнопок «+ Задача» и «+ Подзадача» нет ни на доске, ни в списке, ни в карточке.

**C2 Создать Bug**
- C2.1 Дано: пустое описание. Действие: переключить тип на Bug. Ожидаю: подставлен шаблон (Шаги воспроизведения / Ожидаемый результат / Фактический результат).
- C2.2 Дано: описание уже введено. Действие: переключить на Bug. Ожидаю: текст не заменён.
- C2.3 Дано: подставлен шаблон. Действие: вернуть Task. Ожидаю: описание осталось как есть. Создать Bug → в карточке тип Bug и описание из формы.

**C3 Создать Subtask из карточки**
- C3.1 Дано: `clara_member`, карточка Task. Действие: «+ Подзадача». Ожидаю: тип Subtask, «Родитель» заполнен этой задачей и может быть заменён.
- C3.2 Дано: переключатель типа в обычном диалоге. Действие: выбрать Subtask. Ожидаю: появилось обязательное «Родитель»; поиск по ключу и названию находит только неархивные Task и Bug проекта (подзадачи и архивные не находятся).
- C3.3 Дано: Subtask с родителем. Действие: переключить на Task или Bug. Ожидаю: поле скрыто, значение сброшено.
- C3.4 Дано: заполнено название, «Создать». Ожидаю: в карточке подзадачи родитель только чтение; в родителе она в списке «Подзадачи».

**C4 Ошибки валидации**
- C4.1 Дано: пустая форма. Действие: «Создать». Ожидаю: кнопка не была отключена; «Введите название» под полем, фокус на названии.
- C4.2 Дано: название 101 символ. Ожидаю: «Не больше 100 символов».
- C4.3 Дано: Subtask без родителя. Ожидаю: «Выберите родительскую задачу», фокус на «Родитель».
- C4.4 Дано: ошибки показаны. Действие: исправить и «Создать». Ожидаю: диалог закрылся.

**C5 Отмена**
- C5.1 Дано: пустая форма. Действие: «Отмена», крестик, Esc (по отдельности). Ожидаю: закрывается сразу.
- C5.2 Дано: введено название или изменено поле. Действие: «Отмена», крестик, Esc. Ожидаю: «Закрыть без сохранения?»; «Остаться» оставляет форму с данными; «Закрыть без сохранения» закрывает и отбрасывает ввод.
- C5.3 Дано: любая форма. Действие: клик вне диалога. Ожидаю: диалог не закрывается.

**C6 Ошибка сервера**
- C6.1 Дано: остановлен бэкенд. Действие: «Создать». Ожидаю: на время запроса индикатор поверх диалога (текст кнопки не меняется); затем общее сообщение приложения, диалог открыт, введённые данные на месте; после восстановления повторное «Создать» срабатывает.
