# Карточка задачи (Task, Bug, Subtask)

Связан с [01-scope.md](01-scope.md) и [02-scenarios-and-permissions.md](02-scenarios-and-permissions.md). Макеты: [wireframes/card/](wireframes/card/) — `task.svg` (Task и Subtask), `tabs.svg` (вкладки «Время» и «История»), `popups.svg` (выпадающие окна и диалоги), `states.svg` (состояния; кадр 9 — действия с комментариями для admin и owner). Вложения в первой версии не делаются (после релиза, Q-05).

## 1. Назначение и доступ
Единое место просмотра и правки задачи: описание, подзадачи, связи, ссылки, комментарии, списание времени, история и поля.
- Открывается боковой панелью поверх текущего вида (доска или «Все задачи»): к адресу вида добавляется `?task=PROJ-123`, например `/p/PROJ/board/:id?task=PROJ-123`. Адрес `/p/PROJ/tasks/PROJ-123` — входная ссылка (из Telegram, из чата): маршрут-редирект ведёт на последний использованный вид проекта (если его нет — на первую доску) с `?task=PROJ-123`.
- Панель модальная: фон затемняется, закрывается крестиком, клавишей Esc и кликом вне панели.
- Просмотр: все роли (`task-view`). Права на действия: раздел 7.

## 2. Типы и состав полей
| Поле | Task | Bug | Subtask |
|---|---|---|---|
| Статус | ✓ | ✓ | ✓ |
| Приоритет (Low / Medium / High / Critical) | ✓ | ✓ | ✓ |
| Тип | меняется Task ↔ Bug | меняется Task ↔ Bug | фиксирован |
| Направление | ✓ | ✓ | ✓ |
| Исполнитель | ✓ | ✓ | ✓ |
| Ревьюер | ✓ | ✓ | ✓ |
| К дате | ✓ | ✓ | ✓ |
| Оценка (время) | ✓ | ✓ | ✓ |
| Затрачено (сумма списаний, только чтение) | ✓ | ✓ | ✓ |
| Родитель | — | — | только чтение (задаётся при создании) |

Теги (чипы и «+ Тег») показываются под названием у всех трёх типов. Блоки: описание; подзадачи (у Task и Bug); связи; ссылки; вкладки «Комментарии», «Время», «История». Единственное отличие Bug от Task при создании: в описание подставляется шаблон (шаги, ожидаемое, фактическое).

Системные данные в шапке: ключ (`PROJ-123`, с кнопкой копирования ссылки), «создана N назад · X» и «обновлена N назад» (нейтральная форма без рода глагола, Q-22; по `updatedAt`; кто обновил, не показывается: `updatedAt` меняют и правки полей, и комментарии), значок типа.

## 3. Раскладка
- **Шапка:** ключ и значок типа слева; справа звёздочка (подписка), меню «⋯» (копировать ссылку, архивировать), крестик.
- **Левая колонка:** название (крупно), под ним теги, описание, подзадачи, связи, ссылки, вкладки активности.
- **Правая колонка:** панель полей на слегка затенённом фоне, компактно: название поля слева, значение справа, одна строка на поле. Дополнительная строка мелким шрифтом под значением только там, где она нужна: «Назначить на меня» под Исполнитель, «по подзадачам: …» под Оценкой и Затрачено. Порядок полей как в таблице выше.
- На узких экранах панель полей уходит над содержимым; адаптив карточки решаем позже по дизайну.

## 4. Поведение
**Название.** Правится кликом; Enter сохраняет, Esc отменяет; пустое название не сохраняется. Ограничения длины: название до 100 символов, описание до 5000, комментарий до 2000; при превышении под полем ошибка «Не больше N символов».

**Описание.** Markdown. В режиме просмотра показывается отрендеренный текст; клик по полю описания открывает редактор с кнопками форматирования и переключателем «Редактор / Просмотр» (отдельной кнопки «Редактировать» нет). Пустое описание показывает подсказку «Добавьте описание», клик по ней тоже открывает редактор. У viewer и в архивной задаче поле не кликабельно. Сохраняется явной кнопкой «Сохранить», «Отмена» возвращает прежний текст. Если закрыть панель с несохранёнными изменениями, показывается подтверждение «Закрыть без сохранения?» с двумя кнопками: «Остаться» и «Закрыть без сохранения» ([12](12-ui-rules.md), раздел 2). Рендер и очистка разметки — по правилу [12](12-ui-rules.md), раздел 9 (`ngx-markdown`, санитайзер Angular).

**Поля панели.** Каждое поле сохраняется сразу после выбора значения. Оценка и срок сохраняются по Enter или потере фокуса. При ошибке сервера показывается сообщение «Не удалось сохранить поле «…»», значение возвращается на прежнее. Подробности выбора:
- Статус: список статусов проекта. Для статуса с `requiresReason` (по умолчанию Cancelled и Blocked) открывается диалог «Причина *»; кнопка «Подтвердить» всегда активна, при пустой причине под полем ошибка «Укажите причину»; отмена диалога оставляет прежний статус; причина сохраняется комментарием.
- Исполнитель и Ревьюер: поиск среди участников проекта (в списке только не деактивированные; уже назначенный деактивированный показан серым с подписью «(деактивирован)», его можно только снять; образец — кадр 4 в [wireframes/board/states.svg](wireframes/board/states.svg)); в списке первым пунктом «Я», затем «Не назначен»; под полем «Исполнитель» ссылка «Назначить на меня» (то же, что выбрать «Я»).
- К дате: выбор в календаре, очистка кнопкой «Сбросить»; просроченный срок у незакрытой задачи показывается красным и с иконкой часов (цвет не единственный сигнал).
- Оценка: формат `2h 30m` (часы и минуты, без дней и недель); пусто разрешено.
- Теги (под названием): «+ Тег» открывает ввод с подсказками из тегов проекта; если такого нет, пункт «Создать «…»» (право `tag-create`); чип снимается крестиком (✕ «Убрать тег», без подтверждения: тег остаётся в проекте). Если тег с таким названием создали одновременно, ответ 409 `name_taken` несёт `details.tag`: он ставится на задачу без сообщения. Сохраняются сразу, как поля панели.
- Затрачено: только чтение, сумма списаний этой задачи.

**Подзадачи.** Заголовок «Подзадачи N из M» с мини-прогрессом закрытых. Строка: ключ, название, статус, аватар исполнителя. Клик открывает подзадачу в этой же панели. «+ Подзадача» открывает диалог создания задачи с типом Subtask и подставленным родителем (см. [05-create-task-dialog.md](05-create-task-dialog.md)); нельзя создать подзадачу у подзадачи. Прогресс считает закрытые подзадачи по статусам категории done. У родительской задачи рядом с полями «Оценка» и «Затрачено» показывается отдельная строка «по подзадачам: …» (сумма оценок и сумма затраченного времени всех её подзадач). Собственные оценка и затраченное время родителя не заменяются и в эту сумму не входят, поэтому двойного счёта нет. Строка видна, только если у задачи есть подзадачи. У строк «по подзадачам» обязательны пояснения-подсказки: «Сумма оценок подзадач» и «Сумма времени, затраченного на подзадачи» (описать в задаче на фронт).

**Связи.** Типы: «Блокирует», «Заблокирована» (`blocks` / `blocked_by`); связей «Связана» и «Дубликат» нет (Q-23, I-07). «+ Связь» открывает окно: тип связи и поиск задачи по ключу или названию (только того же проекта). Связи сгруппированы по типам, у строки статус задачи и значок 🗑; удаление спрашивает подтверждение «Удалить связь с PROJ-144?». Нельзя связать задачу с самой собой и создать цикл blocks. Бейдж «заблокировано» на карточке на доске ставится автоматически, пока есть незакрытая блокирующая задача.

**Ссылки.** Список URL с названием (например merge-request). «+ Ссылка»: адрес (обязателен, должен начинаться с http:// или https://) и название (необязательно). Удаление ссылки: 🗑 и подтверждение «Удалить ссылку?».

**Комментарии.** Счётчик на вкладке — `commentCount` из `TaskDetail`; у вкладок «Время» и «История» счётчика нет (число известно только после загрузки списка). Плоский список от старых к новым, поле ввода внизу (markdown). У комментария: аватар, имя, время, пометка «изменён». Действия: «Ответить» (вставляет `@username` в поле); у **своего** комментария также «Изменить» и «Удалить» (любая роль, включая viewer); у **чужого** admin и owner видят только «Удалить», остальные — только «Ответить» (править чужой комментарий нельзя никому: `updateComment` отвечает 403). «Удалить» спрашивает подтверждение «Удалить комментарий?» (ответы и упоминания в других комментариях остаются). Упоминание создаёт уведомление (в запросе передаётся `mentions: [userId]`). Если комментариев больше 20, показываются последние 20 и кнопка «Показать ещё»: загруженная страница присоединяется к ленте, записи объединяются по `id` (дубли отбрасываются). Свой новый комментарий добавляется в ленту из ответа на `POST`, а не повторной загрузкой. Текст комментария рендерится по правилу [12](12-ui-rules.md), раздел 9 (то же, что у описания: комментарий пишет любая роль, очистка — на фронте).

**Время.** Вкладка «Время»: итог «Затрачено X из Y» (Y — оценка) и ссылка «Списать время» (переводит фокус в форму; кнопка формы называется «Списать»), список записей (дата, автор, длительность, комментарий), свои записи можно изменить и удалить (admin/owner — любые); удаление спрашивает подтверждение «Удалить запись о времени?». Форма «Новая запись»: время (обязательное, `2h 30m`), дата (по умолчанию сегодня), комментарий (необязателен), кнопка «Списать». Длительность — от 1 минуты до 24 часов за запись, дата не позже завтрашней по UTC, в прошлое без ограничений ([backend/07](backend/07-comments-worklogs-watches.md), раздел 3). У viewer вкладка «Время» доступна для чтения без формы.

**История.** Лог изменений (кто, что, было → стало, когда), сгруппирован по дням. Строка в нейтральной форме без рода глагола: «Иван П. · Статус: To do → In progress», «Иван П. · Задача создана» (Q-22). Что попадает в лог: статус, исполнитель, ревьюер, приоритет, тип, направление, теги, срок, оценка, связи, ссылки, создание. Комментарии и списания времени в историю не дублируются.

**Подписка.** Звёздочка включает и выключает подписку на уведомления по задаче. Автор задачи, исполнитель и ревьюер подписаны автоматически; также автоматически подписываются автор комментария и упомянутые в нём.

**Архивация.** Меню «⋯» → «Архивировать» (своя задача или admin/owner). Подтверждение «Архивировать задачу PROJ-N?» показывается всегда; у задачи с подзадачами в нём добавляется строка «Будут архивированы и N подзадач». Восстановление родителя возвращает все его подзадачи, в том числе архивированные отдельно (служебного поля каскада нет, Q-23, I-16). Восстановить подзадачу при архивном родителе нельзя: ответ 409 `parent_archived` — «Сначала восстановите родительскую задачу PROJ-N». Архивная задача открывается с баннером «Задача в архиве, редактирование недоступно» и кнопкой «Восстановить» (только admin/owner); поля и комментарии доступны только для чтения.

## 5. Состояния
Загрузка (индикатор в панели); задача не найдена или нет доступа; роль viewer (нет «+ Тег», «+ Подзадача», «+ Связь», «+ Ссылка» и формы времени, поля без правки, комментарии доступны); архивная; пустое описание; редактирование описания; закрытие с несохранённым описанием; диалог причины. Ошибки сети и сервера (загрузка карточки, автосохранение поля, отправка комментария) отдельных экранов не имеют: показывается общее сообщение приложения, у загрузки и сохранения есть «Повторить», изменённое поле откатывается. **Пустые вкладки и блоки.** Блоки «Подзадачи», «Связи» и «Ссылки» без записей показывают только кнопку добавления («+ Подзадача», «+ Связь», «+ Ссылка»), у viewer блок скрыт целиком; вкладка «Комментарии» — «Комментариев пока нет»; вкладка «Время» — «Списаний пока нет» (форма «Новая запись» остаётся, у viewer её нет); вкладка «История» никогда не пуста: первая запись — создание задачи. Теги без значений — только «+ Тег». Подробно: `wireframes/card/states.svg`. Выпадающие окна: `wireframes/card/popups.svg`.

## 6. Адреса и обновление данных
Открытая задача — параметр `?task=PROJ-123` адреса текущего вида: `/p/PROJ/board/:id?task=PROJ-123`, `/p/PROJ/tasks?q=…&page=2&task=PROJ-123`. Закрытие панели убирает только `task`, остальные параметры (фильтры, страница) остаются; кнопка «Назад» браузера закрывает панель. Переход по уведомлению в другой проект открывает последний вид того проекта с `?task=`. `/p/PROJ/tasks/PROJ-123` — только входная ссылка (старые и внешние ссылки): редирект (без записи в историю) на последний использованный вид проекта с `?task=PROJ-123`. Ссылки в Telegram строятся сразу как `/p/PROJ/tasks?task=PROJ-123` ([backend/08](backend/08-notifications-and-telegram.md), раздел 5). Данные карточки обновляются при возврате на вкладку и после своих действий; параллельная правка того же поля решается последним сохранением, значение обновляется по ответу сервера.

**Автосохранение полей.** Запросы по одному полю выполняются по очереди (`concatMap`): второе изменение того же поля уходит после ответа на первое. При ошибке значение откатывается к последнему успешному ответу сервера, а не к значению до первого изменения. Набор тегов (`tagIds`) уходит на сервер целиком, поэтому изменения тегов идут по той же очереди. После закрытия панели перезапрашивается активный вид (доска или список), чтобы показать изменённые поля.

## 7. Права
| Действие | Ключ |
|---|---|
| Открыть карточку | `task-view` |
| Править поля, название, описание, подзадачи | `task-update` (создание подзадачи — `task-create`) |
| Сменить статус | `task-move` |
| Создать тег на лету | `tag-create` |
| Связи и ссылки | `link-manage` |

| Комментарии | `comment-create`; свой: править — `comment-update`, удалять — `comment-delete`; чужой комментарий admin и owner только удаляют (`comment-delete`), править его нельзя |
| Списание времени | `worklog-create`; править и удалять своё — `worklog-update`, `worklog-delete`, чужое — admin/owner |
| Подписка | `watch-toggle` |
| Вложения — после релиза | ключи `attachment-add`, `attachment-delete` в резерве, ручек нет |

## 8. API
Группы OpenAPI: Tasks, Links, Comments, Worklogs, Watches, а также Members и Tags (выбор исполнителя и тегов). Контракт — [backend/openapi/openapi.yaml](backend/openapi/openapi.yaml); ТЗ — [backend/04-tasks-core.md](backend/04-tasks-core.md), [05](backend/05-links-search-list.md), [06](backend/06-boards-and-move.md), [07](backend/07-comments-worklogs-watches.md).
- Карточка открывается по ключу из `?task=` (`GET /projects/:projectId/tasks/by-key/:key`; `projectId` фронт берёт из адреса `/p/PROJ/...` по загруженному `GET /projects`): в ответе поля, связи, ссылки, признак подписки и суммы оценок и времени по подзадачам (считает бэкенд). Список подзадач блока «Подзадачи» — отдельным запросом `GET /tasks/:id/subtasks`.
- Статус меняется только ручкой переноса `POST /tasks/:id/move` (с причиной для статусов с `requiresReason`), `PATCH /tasks/:id` статус не принимает.
- Поиск задач для связей — `GET /projects/:projectId/tasks/search`.

## 9. Сценарии
- **T1 Открыть карточку** с доски или по ссылке; закрыть крестиком, Esc или кликом вне панели.
- **T2 Изменить поля** (статус, исполнитель, срок, оценка, теги): автосохранение, откат при ошибке.
- **T3 Сменить статус с причиной:** Cancelled / Blocked → диалог → подтверждение или отмена.
- **T4 Отредактировать описание:** сохранить, отменить, закрыть панель с несохранённым текстом.
- **T5 Подзадачи:** добавить, открыть, видеть прогресс и сумму оценок и времени по подзадачам.
- **T6 Связи и ссылки:** добавить связи «Блокирует» / «Заблокирована», удалить, ошибки (сама на себя, цикл, чужой проект, неверный адрес).
- **T7 Комментарий:** написать, ответить через `@`, изменить и удалить свой.
- **T8 Списать время:** `2h 30m`, дата, комментарий; изменить и удалить свою запись.
- **T9 Посмотреть историю.**
- **T10 Подписаться** звёздочкой.
- **T11 Архивировать и восстановить.**
- **T12 Роль viewer:** чтение и комментарии.
- **T13 Потеря прав или архивация задачи** при открытой панели: сообщение и перезапрос прав.
Соответствие сценариям из 02: M3, M5–M9, M11, M13, M14, V1–V3.

## 10. Оценка трудозатрат фронта: ≈ 117 ч
Оболочка панель/страница, роутинг, закрытие 10; шапка и название 5; панель полей с автосохранением (≈ 8 задач по 3 ч, эпик «Общие поля» идёт на неделю раньше карточки) 24; описание и просмотр markdown (с правилами очистки 12 §9) 13; подзадачи 10; связи (только «Блокирует» и «Заблокирована») 9; ссылки 4; комментарии с упоминаниями 16; списание времени 10; история 8; подписка 3; состояния и права 5.

Не входит в сумму: вложения (≈ 25 ч) — после релиза (Q-05). Снято упрощениями Q-23: связи relates и duplicates −3 (I-07), восстановление без служебного поля каскада −3 (I-16).
