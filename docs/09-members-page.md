# Страница «Участники»

Связан с [01-scope.md](01-scope.md), [02-scenarios-and-permissions.md](02-scenarios-and-permissions.md), [08-project-settings-page.md](08-project-settings-page.md). Макеты: [wireframes/members/](wireframes/members/) (`list.svg` — список для owner, admin и member, `dialogs.svg` — добавление и удаление).

## 1. Назначение и доступ
Список людей проекта с ролями; здесь добавляют участников, меняют роли и удаляют из проекта.
- Маршрут: `/p/PROJ/members`; открывается из меню проекта (⚙) → «Участники».
- Просмотр списка: все роли проекта (`member-list`). Добавление, смена роли и удаление: owner и admin (`member-add`, `member-role-change`, `member-remove`) с одинаковыми возможностями; единственное ограничение — owner изменить и удалить нельзя (Q-23, I-03).
- Member и viewer видят страницу только для чтения: без кнопки «+ Участники», выпадающих списков ролей и кнопок удаления.

## 2. Раскладка
- Заголовок «Участники» и число участников; поиск по имени и `username`; справа кнопка «+ Участники» (по праву).
- Таблица: Участник (аватар-инициалы, имя, `@username`; у себя пометка «(вы)»; у деактивированного подпись «(деактивирован)» и вторичный цвет текста без прозрачности, [12](12-ui-rules.md), раздел 3; приглашённый после «Новой ссылки» выглядит как обычный участник, Q-32 а) · Роль (выпадающий список или метка роли) · удаление (🗑, «Удалить из проекта»).

## 3. Поведение
**Список.** Все участники проекта, включая деактивированных. Порядок по убыванию полномочий: owner, admin, member, viewer; внутри роли по алфавиту. Пагинации нет; поиск работает на клиенте по уже загруженному списку.

**Кто что может.**
| Действие | owner и admin | member / viewer |
|---|---|---|
| Видеть список | ✓ | ✓ |
| Добавить участников | ✓ (роли admin, member, viewer) | — |
| Менять роли | у всех, кроме себя и owner | — |
| Удалять | всех, кроме себя и owner | — |
Свою роль и роль owner через эту страницу не меняют: владение передаёт только системный администратор в администрировании проектов ([10](10-account-and-admin.md)).

**Смена роли.** Выпадающий список в строке: Admin / Member / Viewer; значение сохраняется сразу, при ошибке возвращается прежнее. Права пользователя в проекте обновляются при следующей загрузке его прав (при входе в проект или после ответа 403).

**Добавление.** Кнопка «+ Участники» открывает окно: поле выбора нескольких людей с поиском по имени и `username` и одна роль для всех (по умолчанию Member). Кандидаты загружаются только поиском, от 2 символов (после обрезки пробелов): пока введено меньше, список пуст с подсказкой «Введите имя или логин (от 2 символов)» и запрос не отправляется; предлагаются только активные пользователи системы, которых нет в проекте (не более 50). Уже выбранные люди остаются в поле при смене запроса. Кнопка «Добавить (N)» активна всегда; если никто не выбран, под полем ошибка «Выберите хотя бы одного человека». Под полем подсказка: «Нужного человека нет в списке? Попросите системного администратора пригласить его.» Если по запросу никого нет, список показывает «Никого не найдено» и ссылку «Сбросить» (очищает запрос). Новые участники появляются в списке сразу.

**Удаление.** Окно подтверждения без чисел (Q-23, I-17): «Участник будет снят с исполнителя и ревьюера всех задач проекта (запись попадёт в историю задач)». Комментарии, списания времени и история сохраняются; доступ к проекту пропадает. Owner удалить нельзя. Деактивированного участника удалить можно, его роль при этом не меняется.

**Деактивированные.** С подписью «(деактивирован)», роль только для чтения, удаление доступно. Снять деактивацию может только системный администратор. **Приглашённые** (системный администратор выдал «Новую ссылку» участнику проекта) остаются участниками и отображаются как обычные: `active = true`, без подписи; их можно назначать исполнителем и ревьюером.

## 4. Состояния
Каждое состояние имеет свой кадр ([12](12-ui-rules.md), раздел 3):
- загрузка (индикатор поверх таблицы);
- пусто: невозможно, в проекте всегда есть владелец; поэтому отдельного пустого списка нет;
- поиск ничего не нашёл: «Никого не найдено» и кнопка «Сбросить»;
- только чтение (member, viewer): нет «+ Участники», выпадающего списка роли и 🗑;
- окно добавления: до ввода 2 символов (подсказка «Введите имя или логин (от 2 символов)»), загрузка кандидатов (индикатор в списке), поиск без совпадений («Никого не найдено», «Сбросить»), ошибка «Выберите хотя бы одного человека»;
- окно подтверждения удаления участника.
Ошибки сети и сервера — общее сообщение приложения с «Повторить».

## 5. Права
| Действие | Ключ |
|---|---|
| Открыть список | `member-list` |
| Добавить | `member-add` |
| Сменить роль | `member-role-change` |
| Удалить | `member-remove` |
Ограничение «не трогать owner» проверяет бэкенд; фронт скрывает недоступные элементы по роли пользователя (`isProjectAdmin`) и роли строки.

## 6. API
Группы OpenAPI: Members. Контракт — [backend/openapi/openapi.yaml](backend/openapi/openapi.yaml); ТЗ — [backend/02-projects-members-permissions.md](backend/02-projects-members-permissions.md).
- Кандидаты для добавления — `GET /projects/:projectId/member-candidates?search=`: активные пользователи системы, которых нет в проекте, не более 50; `search` обязателен и не короче 2 символов (иначе 422), поэтому без запроса фронт не обращается к ручке.

## 7. Сценарии
Продолжают P1 и P2 документа 02.
- **MB1 Посмотреть и найти участника.**
- **MB2 Добавить нескольких людей** с одной ролью.
- **MB3 Сменить роль** участнику (owner и admin одинаково).
- **MB4 Удалить участника** и прочитать, что он будет снят с задач.
- **MB5 Строка owner:** у неё нет выпадающего списка роли и удаления, у admin те же права, что у owner.
- **MB6 Просмотр member и viewer:** только чтение.

## 8. Оценка трудозатрат фронта: ≈ 30 ч
Страница и список 8; поиск 2; роли и выпадающий список 2; окно добавления с мультивыбором и поиском кандидатов от 2 символов 12; окно удаления (текст без чисел) 2; состояния и права 4. Снято упрощениями Q-23: admin без ограничений, кроме owner −4 (I-03), окно удаления без чисел −2 (I-17).

## 9. Открытые вопросы
Нет. Вне скоупа: самостоятельный выход участника из проекта, приглашение людей прямо из проекта (приглашает только системный администратор).

## Приёмка
Формат и сид — как в [04](04-task-card.md), раздел «Приёмка». Состав `DEMO`: `anna_owner` — owner, `boris_admin` — admin, `clara_member` и `denis_member` — member, `eva_viewer` — viewer, `fedor_inactive` — member (деактивирован); не в проектах: `gleb_invited`, `hanna_free` ([backend/02](backend/02-projects-members-permissions.md), §9). Роль с правом — `anna_owner`, `boris_admin`; `eva_viewer` — viewer.

**MB1 Посмотреть и найти**
- MB1.1 Дано: `anna_owner`, `/p/DEMO/members`. Ожидаю: заголовок «Участники» с числом 6; порядок owner, admin, member, viewer, внутри роли по алфавиту; у себя пометка «(вы)»; `fedor_inactive` с подписью «(деактивирован)» и вторичным цветом текста.
- MB1.2 Дано: поиск «cla», затем `@denis`, затем «zzz». Ожидаю: фильтрация по имени и логину; «Никого не найдено» и «Сбросить».
- MB1.3 Дано: загрузка и ошибка сети. Ожидаю: индикатор, затем общее сообщение.

**MB2 Добавить нескольких людей**
- MB2.1 Дано: `boris_admin`, «+ Участники». Действие: открыть окно, затем ввести `h`, затем `ha`. Ожидаю: до 2 символов список пуст с подсказкой «Введите имя или логин (от 2 символов)», запросов нет; на `ha` — `hanna_free` (только активные пользователи не из проекта; `gleb_invited` без логина не предлагается); роль по умолчанию Member; есть подсказка «Нужного человека нет в списке?».
- MB2.2 Дано: окно без выбранных. Действие: «Добавить (N)». Ожидаю: кнопка активна, ошибка «Выберите хотя бы одного человека».
- MB2.3 Дано: выбраны двое, роль Viewer. Действие: «Добавить». Ожидаю: оба в списке с ролью Viewer.
- MB2.4 Дано: поиск `zzz`. Ожидаю: в окне «Никого не найдено» и «Сбросить» (очищает запрос и возвращает подсказку про 2 символа).
- MB2.5 Дано: участник проекта (например, `denis_member`), которому системный администратор выдал «Новую ссылку». Ожидаю: в списке участников он выглядит как обычный (без подписи и серого цвета), его можно выбрать исполнителем и ревьюером.

**MB3 Сменить роль**
- MB3.1 Дано: `anna_owner` и отдельно `boris_admin`. Действие: роль `denis_member` → Admin, → Viewer. Ожидаю: сохраняется сразу; доступные значения Admin / Member / Viewer; после входа `denis_member` права соответствуют новой роли.
- MB3.2 Дано: остановлен бэкенд. Действие: сменить роль. Ожидаю: значение вернулось, общее сообщение.
- MB3.3 Дано: строка деактивированного. Ожидаю: роль только чтение.

**MB4 Удалить участника**
- MB4.1 Дано: `boris_admin`, `clara_member` назначена исполнителем. Действие: крестик в её строке. Ожидаю: текст «Участник будет снят с исполнителя и ревьюера всех задач проекта (запись попадёт в историю задач)» без чисел.
- MB4.2 Дано: подтверждение. Ожидаю: из списка пропала; её задачи без исполнителя, в истории запись; комментарии на месте; проект ей больше не доступен.
- MB4.3 Дано: `fedor_inactive`. Ожидаю: удалить можно, роль не менялась.

**MB5 Строка owner**
- MB5.1 Дано: `boris_admin`. Ожидаю: у `anna_owner` и у своей строки нет ни выпадающего списка роли, ни удаления.
- MB5.2 Дано: `anna_owner`. Ожидаю: то же для своей строки; возможности admin и owner одинаковы.

**MB6 Просмотр member и viewer**
- MB6.1 Дано: `clara_member` и `eva_viewer`. Ожидаю: список виден; нет «+ Участники», выпадающих списков, крестиков.
- MB6.2 Дано: `denis_member` временно получил роль Admin и открыл страницу; `anna_owner` в другой сессии вернула ему Member. Действие: сменить роль другому участнику. Ожидаю: 403, общее сообщение, права перезапрошены, элементы правки скрыты.
