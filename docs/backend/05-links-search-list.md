## 1. Цель и границы
Дать фронту связи между задачами, ссылки на внешние ресурсы, поиск задач для выбора (родитель, связанная задача) и постраничный список «Все задачи» с фильтрами и сортировкой.
- Входит: TaskLink, TaskUrl; признак `blocked`; ручки раздела 5; расширение `TaskDetail` полями `links`, `urls`, `blocked`; тестовые данные.
- Не входит: доски и карточки по колонкам (пакет 6), комментарии и время (пакет 7). Поэтому `spentMinutes` в списке пока 0.

## 2. Связи (TaskLink)

**Модель.** `id`, `projectId`, `fromTaskId`, `toTaskId`, `type` (`blocks`). Обе задачи — в одном проекте, `from ≠ to`.
- `blocks`: «from блокирует to». Обратную сторону («to заблокирована from») отдельной записью не хранят.
- На вход принимается `type`: `blocks`, `blocked_by`. `blocked_by` для задачи A и цели B сохраняется как `blocks` с `from = B`, `to = A`.
- В ответах связь описана с точки зрения читаемой задачи: `type` — `blocks` или `blocked_by`.
- Связей `relates` и `duplicates` в первой версии нет (после релиза, Q-23, I-07): такое значение `type` в запросе — 422 (`fields.type = invalid`).

**Правила.**
- Связь с самой собой: 422 (`fields.targetTaskId = "same_task"`).
- Целевая задача не найдена в этом проекте (в том числе из другого проекта): 422 (`fields.targetTaskId = "not_found"`); архивная: 422 (`"archived"`). Исходная задача архивная: 409 `task_archived`.
- Такая связь уже есть в том же направлении: 409 `link_exists`.
- Цикл `blocks` (A блокирует B, B — C, C — A): добавление, замыкающее цикл, запрещено — 409 `link_cycle`. Нельзя добавить «A блокирует B», если из B по цепочке `blocks` достижима A; прямая обратная пара (A блокирует B и B блокирует A) — частный случай цикла. В цепочке учитываются связи всех задач проекта, **включая архивные** (связи при архивации остаются, и восстановленная задача не должна замкнуть цикл). Два одновременных запроса «A→B» и «B→A» не создают цикл: один успешен, второй получает 409 `link_cycle`.
- Связи не удаляются при архивации задач; архивная задача отображается в списке связей с пометкой.
- Каждое добавление и удаление пишет событие `link_added` / `link_removed` в историю **обеих** задач (в `newValue`/`oldValue` — `{ id: id другой задачи, label: её ключ }` и в `field` — тип связи с точки зрения этой задачи); у обеих задач обновляется `updatedAt`.

**`blocked`.** У задачи `blocked = true`, если есть связь `blocks`, где она на стороне `to`, а блокирующая задача не архивная и её статус не категории `done`. Это вычисляемое поле (не хранится); считается при формировании `TaskDetail`, `TaskSummary` и (пакет 6) карточек досок. Не влияет на возможность менять статус.

## 3. Ссылки (TaskUrl)
`id`, `taskId`, `url`, `title?`, `createdAt`.
- `url`: начинается с `http://` или `https://`, не длиннее 2000 символов, должен быть корректным URL (без пробелов и управляющих символов); иначе 422 (`fields.url = "invalid"`). `title`: до 100 символов, необязательно; пустая строка хранится и отдаётся как `null`.
- Одинаковые адреса в одной задаче допустимы. Редактирования ссылки нет (удалить и добавить заново).
- Не больше 50 ссылок на задачу (защитный предел): 422 (`fields.url = "limit"`).
- События `url_added` / `url_removed` (`newValue` / `oldValue` = `{ id: id ссылки, label: title или url }`).

## 4. Формат связей и ссылок в `TaskDetail`
Пакет 5 добавляет в `TaskDetail` (пакет 4):
- `links`: `[{ id, type, task }]`, где `task` — `{ id, key, title, status { id, name, color, category }, archived }`. Порядок: по типу (`blocks`, `blocked_by`), внутри — по номеру задачи (числу, а не строке: `PROJ-99` раньше `PROJ-100`).
- `urls`: `[{ id, url, title, createdAt }]` по возрастанию `createdAt`.
- `blocked`: булево.
В `TaskSummary` добавляется только `blocked`.

## 5. Ручки

### Связи и ссылки
| Ручка | Права | Поведение |
|---|---|---|
| `POST /tasks/:taskId/links` `{ type, targetTaskId }` | `link-manage` | Добавляет связь по правилам раздела 2. 201 `{ link: { id, type, task } }` (с точки зрения `taskId`) |
| `DELETE /tasks/:taskId/links/:linkId` | `link-manage` | Удаляет связь, где `taskId` — любая из сторон; иначе 404. Задача архивная: 409 `task_archived`. 204 |
| `POST /tasks/:taskId/urls` `{ url, title? }` | `link-manage` | Добавляет ссылку. 201 `{ url: { id, url, title, createdAt } }` |
| `DELETE /tasks/:taskId/urls/:urlId` | `link-manage` | Удаляет ссылку; чужая или несуществующая: 404. 204 |

Общие ошибки: задача архивная — 409 `task_archived`; не участник — 404.

### Поиск задач (для выбора родителя и связанной задачи)
`GET /projects/:projectId/tasks/search?q=&types=&excludeId=&limit=` — права `task-view`.
- Проект задаётся путём (общий слой, [b02, раздел 4](02-projects-members-permissions.md)); не участник — 404.
- `q` — до 100 символов; после `trim` пустой `q` отдаёт последние обновлённые задачи. По названию ищется подстрока без учёта регистра (символы `%`, `_`, `\` — обычные символы). По ключу ищется только запрос, похожий на номер: `N` или `-N` (номер задачи как текст содержит `N`) либо `KEY-N` (ключ задачи содержит запрос целиком, без учёта регистра: `demo-1` находит `DEMO-1`, `DEMO-10`). Любой другой запрос (`de`, `mo`, `demo`) ищет только по названию, а не по ключу, поэтому часть ключа проекта не возвращает весь проект.
- `types` — через запятую: `task`, `bug`, `subtask` (для выбора родителя: `task,bug`); без параметра — все типы.
- `excludeId` — исключить задачу (чтобы не предлагать саму себя); проверяется только формат UUID, задача не из проекта не ошибка.
- `limit` — от 1 до 20, по умолчанию 10. Архивные задачи не возвращаются никогда.
- Порядок: точное совпадение ключа, затем ключ содержит `q`, затем название содержит `q`; внутри группы — по `updatedAt` от новых к старым.
- Ответ: `{ items: [{ id, key, type, title, status { id, name, color, category } }] }`.

### Список «Все задачи»
`GET /projects/:projectId/tasks?q=&status=&assignee=&reviewer=&priority=&type=&subsystem=&tag=&archived=&sort=&page=&size=` — права `task-view`.

Параметры:
| Параметр | Значения |
|---|---|
| `q` | подстрока названия без учёта регистра; по ключу — только запрос вида `N`, `-N`, `KEY-N` (см. поиск выше); до 100 символов, после `trim` пустой — фильтра нет |
| `status` | UUID статусов через запятую |
| `assignee`, `reviewer` | UUID участников, `me` (текущий пользователь), `none` (не назначен), через запятую |
| `priority` | `low`, `medium`, `high`, `critical` через запятую |
| `type` | `task`, `bug` через запятую (`subtask` как значение фильтра не допускается: подзадачи не бывают строками) |
| `subsystem` | UUID направлений или `none` через запятую |
| `tag` | UUID тегов через запятую |
| `archived` | `true` — только архивные задачи (нужен ключ `task-restore`, иначе 403 `forbidden`); по умолчанию `false` — только неархивные |
| `sort` | одно из `key`, `priority`, `dueDate`, `updatedAt` с направлением `:asc` / `:desc` (например `dueDate:asc`); по умолчанию `updatedAt:desc`; другое значение — 422 (`fields.sort = invalid`) |
| `page` | с 1, по умолчанию 1 |
| `size` | `10`, `25` или `50`, по умолчанию 25 |
Неверное значение любого параметра (не UUID, неизвестная константа, размер страницы вне набора): 422 (`fields.<параметр>`). Повтор значения в списке не ошибка (дубли отбрасываются); больше 50 значений — 422 (`fields.<параметр> = too_many`). `page` за последней страницей — 200, `items: []`, `total` как есть. Корректный UUID, которого нет в проекте (удалён или чужой), не ошибка: он отбрасывается из списка значений, а если значений не осталось, фильтр не применяется ([00, раздел 12](00-conventions.md)).

Семантика:
- **Строки списка** — только Task и Bug. Задача `T` совпадает с запросом (`match`), если она (а) имеет нужное состояние архивации (`archived`), (б) подходит под `q` и все заданные фильтры. Значения внутри одного фильтра объединяются по «или», разные фильтры — по «и».
- **Строка попадает в результат, если `match(T)` истинно или `match(S)` истинно хотя бы для одной подзадачи `S` задачи `T`.** Подзадача оценивается теми же `q` и фильтрами (в том числе её собственными исполнителем, статусом и т. д.), поэтому фильтр «Исполнитель = Я» находит задачу, у которой на пользователя назначена только подзадача. Поиск `q` по ключу или названию подзадачи тоже находит родителя.
- **Фильтр `type`** применяется только к самой строке (Task или Bug) и не участвует в проверке подзадач (у них тип всегда `subtask`). Итог: строка попадает в результат, если её тип подходит под `type` и (`match(T)` по остальным условиям или `match(S)` по остальным условиям хотя бы для одной подзадачи).
- `subtaskCount` в строке — все неархивные подзадачи, независимо от фильтров.
- Архивный режим (`archived=true`): в списке только архивные Task и Bug. Активный родитель, у которого отдельно архивирована подзадача, строкой не становится и из-за этой подзадачи в результат не попадает.
- **Сортировка.** `key` — по номеру; `priority` — по весу (`critical` > `high` > `medium` > `low`; `desc` — от `critical`); `dueDate` — по дате, задачи без срока всегда в конце независимо от направления; `updatedAt` — по строке-родителю. При равенстве порядок по номеру задачи по убыванию (стабильная пагинация).
- Ответ: `{ items: [TaskSummary], total }`, `total` — число строк (задач Task и Bug) по условиям выше.
- Для раскрытия строки фронт использует `GET /tasks/:taskId/subtasks` (пакет 4): фильтры на подзадачи при раскрытии не действуют.

Производительность (ориентир, не условие приёмки): проект до 5000 задач, ответ до 300 мс; подзадачи, теги и счётчики приходят в самом ответе ([00, раздел 10](00-conventions.md)).

## 6. Тестовые данные (`DEV_SEED=true`)
К данным пакета 4 добавляются:
- в `DEMO`: связи `blocks` (две задачи в статусе не `done` блокируют третью — у неё `blocked = true`; для одной связи блокирующая задача в `Done`, `blocked = false`), связь на архивную задачу; цепочка из трёх `blocks` без цикла (для проверки отказа при замыкании);
- у 5–6 задач по 1–2 ссылки (merge request, документ);
- в `DEMO` не менее 60 задач суммарно (добавить к 25 из пакета 4), чтобы работала пагинация со страницами 10/25: допускается сгенерировать недостающие скриптом (названия «Тестовая задача N», разные статусы, исполнители, приоритеты, сроки, теги); номера не должны дублироваться (скрипт использует тот же механизм нумерации, что и ручка создания).

## 7. Критерии приёмки
1. `POST /tasks/:id/links` с типом `blocks` и `blocked_by` создаёт связи; в `TaskDetail` обеих задач связь видна с правильной стороны (`blocks` / `blocked_by`), в истории обеих — событие `link_added`; `relates` и `duplicates` — 422 (`fields.type = invalid`).
2. Связь на себя — 422 (`fields.targetTaskId = same_task`); на задачу другого проекта или несуществующую — 422 (`fields.targetTaskId = not_found`); на архивную — 422 (`fields.targetTaskId = archived`); повтор — 409 `link_exists`.
3. Цикл `blocks` (A→B, B→C, затем C→A и A→A через цепочку) — 409 `link_cycle`; прямая обратная пара тоже. Связи архивных задач учитываются: A→B, B→C, затем B архивируется — C→A по-прежнему 409 `link_cycle`. Одновременные запросы «A→B» и «B→A» (повторить не менее 20 раз): один успешен, второй — 409 `link_cycle`.
4. `blocked` = `true` у задачи с незакрытым блокером и `false`, когда блокер в категории `done` или архивный; значение приходит в `TaskDetail` и `TaskSummary`.
5. Удаление связи доступно с обеих сторон, пишет `link_removed` в историю обеих; удаление чужой или несуществующей — 404.
6. Ссылка: `ftp://…`, пустая, без схемы или длиннее 2000 символов — 422 (`fields.url = invalid`); 51-я ссылка на задачу — 422 (`fields.url = limit`); корректная создаётся; удаление работает; события `url_added` / `url_removed`.
7. `GET /projects/:projectId/tasks/search`: поиск по подстроке названия и ключа, `types=task,bug` исключает подзадачи, `excludeId` исключает задачу, архивные не возвращаются, не больше `limit`; чужой проект — 404.
8. Список: по умолчанию `updatedAt:desc`, `size=25`; `size=7`, `sort=foo:asc`, `assignee=abc`, `type=subtask` — 422 (`fields.<параметр>`, например `fields.size`); `q` длиннее 100 символов — 422 (`fields.q = too_long`); `archived=true` для member — 403.
9. Фильтры: `assignee=me` находит задачу, у которой на пользователя назначена только подзадача; `assignee=none`; несколько значений в одном фильтре — «или», между фильтрами — «и»; `q` находит родителя по названию подзадачи.
10. Подзадачи не бывают строками; `subtaskCount` не зависит от фильтров; `total` считает строки.
11. Сортировка `dueDate:asc` и `dueDate:desc` оставляет задачи без срока в конце; `priority:desc` — от `critical`; страницы не пересекаются и не теряют записи при равных значениях сортировки.
12. Для проекта из 60+ задач пагинация даёт ожидаемое число страниц; в ответе `size=50` все строки со своими подзадачами-счётчиками, тегами и исполнителями (без дополнительных запросов клиента); `page` за последней — 200 с `items: []`.
13. Все ручки: в OpenAPI у каждой есть `x-permission`.
14. Неизвестный идентификатор в фильтре: `tag=<удалённый тег>` игнорируется (200, фильтр не применён), `assignee=<uuid не из проекта>,<uuid участника>` фильтрует только по участнику; `tag=abc` — 422 (`fields.tag = invalid`).
15. `archived=true`: в результате только архивные Task и Bug; активный родитель с отдельно архивированной подзадачей в нём отсутствует; архивный родитель вместе с подзадачами присутствует одной строкой.
16. Поиск по номеру: в проекте `DEMO` запрос `q=de` не возвращает задачи без «de» в названии; `q=12` находит `DEMO-12` и задачи с «12» в названии; `q=demo-1` находит `DEMO-1` и `DEMO-10`; `q=demo` ищет только по названию. Пример `pro` для ключа `PROJ` не находит весь проект. Действует и для `listTasks`, `searchTasks`, `getBoardCards`.
17. Порядок связей в `TaskDetail`: внутри типа по числу (`PROJ-99` раньше `PROJ-100`); `sort=foo:asc` — 422 (`fields.sort = invalid`); `assignee=me,me` — 200 (дубль отброшен); 51 значение в фильтре — 422 (`fields.assignee = too_many`); `q` из одних пробелов — фильтра нет.

## 8. Открытые вопросы

1. **Решено:** связи `relates` и `duplicates` — после релиза (Q-23, I-07).
2. **Решено:** предел 50 ссылок на задачу остаётся (защитный).
3. **Решено:** фильтр «Тип» применяется только к самой строке (Task или Bug), подзадачи по нему не проверяются ([06-all-tasks-page.md](../06-all-tasks-page.md), «Фильтры» и «Что в строках»; раздел 5 этого документа).

## 9. Рекомендации (необязательно)
- **Цикл.** Обход графа `blocks` и вставку связи выполнять под блокировкой на проект, например `pg_advisory_xact_lock(hashtextextended('task_link:' || projectId, 0))`, первой в транзакции ([00, раздел 13](00-conventions.md)).
- **Поиск.** В `ILIKE` экранировать `%`, `_`, `\`; проверку «запрос похож на номер» делать перед поиском регулярным выражением; ключ задачи вычисляемый, индекса по нему нет.
- **Список.** Индексы `(projectId, archivedAt, updatedAt)`, `(projectId, assigneeId)`, `(projectId, reviewerId)`, `(projectId, statusId)`, `(parentId)` ([13](../13-data-model-and-permissions.md), раздел 7); подзадачи, теги и счётчики подгружать пакетно, без запроса на каждую строку.
- **Тесты.** Счётчик SQL-запросов при `size=10` и `size=50`, параллельные запросы «A→B» и «B→A» — на усмотрение разработчика.
