# Журнал решений

Решения ментора по спорным вопросам полной версии (вопросы Q-01…Q-45 из аудита документации, октябрь 2026). В документах `docs/` на них ссылаются метками вида «Q-05». Метки находок вида `I-07`, `C-03`, `D-08`, `F-12`, `G-01`, `R-03` — ссылки на удалённый аудит; они оставлены как пометки истории и отдельной расшифровки не имеют.

Для MVP (`docs-short/`) часть решений пересмотрена: Telegram, уведомления, архивация, администрирование и список задач вынесены за MVP ([docs-short/01-scope.md](../docs-short/01-scope.md)).

## Скоуп и план
| № | Вопрос | Решение |
|---|---|---|
| Q-01 | Состав команды и единица оценки | 12–14 учеников, 6–8 ч в неделю, ≈ 20% на онбординг и ревью; оценки — часы ученика; техлидов нет |
| Q-05 | Линия отсечения и «важное» | SSE, сохранённые фильтры, редакторы статусов и досок, вложения — после релиза (ключи `attachment-*` в резерве). Линия отсечения: Telegram-бот → Telegram-вход. «Успеть» всё не обязательно: после обучения доделать с агентами |
| Q-04 | Telegram в скоупе | В ядре, вход подтверждается кнопкой в боте, бот на каждое окружение (стенд — polling, у учеников `TELEGRAM_DRY_RUN`) |
| Q-23 | Пакет упрощений | Принят по пунктам: связи relates/duplicates, архивация проекта, служебное поле каскада архивации и др. — после релиза |
| Q-40 | «Пакет бэкенда готов за неделю до страницы» | Ориентир разработчику бэкенда, не обязательное правило |
| Q-28 | Бэклог в Taiga | Импорт скриптом по REST API Taiga, оценка — кастомным атрибутом «Оценка, ч» |

## Процесс и репозиторий
| № | Вопрос | Решение |
|---|---|---|
| Q-08 | Git-процесс, DoD, ревью, тесты | Ветка `dev`; `main` только у ментора; перекрёстное ревью учеников обязательно; PR как можно меньше (жёсткого лимита нет); тесты не пишем, но спеку и `vitest` не удаляем. Процесс оформляет ментор |
| Q-10 | Архитектура фронта и каркас | Каркас и README в `src/app` делает ментор, с примерами; описание архитектуры — кратко |
| Q-03 | Генерация клиента | `openapi-typescript` (только типы) + тонкие сервисы на `HttpClient`; у каждой операции `operationId` в camelCase |
| Q-02 | Бэкенд и работа фронта до его готовности | Технологии, окружение и темп бэкенда решает его разработчик; моков (Prism, MSW) нет; до готовности пакета фронт работает на константах |
| Q-06 | Иерархия источников правды | У каждой темы один владелец, остальное — ссылки (таблица в [README](README.md)) |
| Q-27 | Хостинг, бэкапы, аудит | Вне скоупа документации; остаётся только требование одного origin для cookie `sid` |
| Q-29 | Prettier и `docs/` | `docs/**/*.md` в `.prettierignore` |

## Бэкенд и контракт
| № | Вопрос | Решение |
|---|---|---|
| Q-30, Q-31, Q-34, Q-41, Q-42, Q-45 | СУБД, автотесты, логи, режим бота, отладочные режимы | Внутреннее дело бэкенда. Требования — только контракт и наблюдаемое поведение; критерии приёмки проверяются через API; технологии — в «Рекомендациях (необязательно)» |
| Q-09 | Тексты ошибок | По умолчанию `message` бэкенда; словарь фронта — только для причин в `fields` и контекстных кодов; перечни `ErrorCode` и `FieldErrorReason` — в OpenAPI |
| Q-39 | Коды ошибок | Коды по операциям — в контракте; у всех операций общие ответы 400 и 500 |
| Q-24 | Повторы, неизвестные id, курсор, время | Таблица повторов в ТЗ; неизвестный UUID в фильтре игнорируется; курсор по (`createdAt`, `id`); «Архивные» — только архивные Task и Bug; «сегодня» по UTC, дату списания фронт передаёт всегда |
| Q-37 | Перенос карточки | Фронт передаёт соседей, которых видит пользователь; карточка встаёт между ними, даже если между ними скрытые задачи; алгоритм ранга — рекомендация |
| Q-38 | Порядок досок | Поля порядка нет: доски в порядке создания («Разработка», затем «Планирование») |
| Q-43 | Поиск по ключу | По ключу ищется только запрос вида номера (`12`, `-12`, `KEY-12`), остальное — по названию |
| Q-14 | Срок Telegram-запроса приглашения | На усмотрение бэкенда, в ТЗ — вариант «продлевается на 5 минут после подтверждения» |
| Q-35 | Текущий пароль при первой смене | Не требуется при `mustChangePassword` (первый вход системного администратора) |
| Q-36 | «Задать пароль» для входящих только через Telegram | Функцию убрать: пароль можно только сменить, если он есть |
| Q-12 | Смена логина | В интерфейсе нет; при необходимости — консольная команда |

## Продукт и интерфейс
| № | Вопрос | Решение |
|---|---|---|
| Q-07 | Адрес открытой задачи | `?task=PROJ-123` у любого вида; `/p/:key/tasks/:taskKey` — входная ссылка (в MVP — отдельная страница задачи) |
| Q-11 | Смена владельца и архивация проекта | Только системный администратор; «опасной зоны» в настройках проекта нет |
| Q-19 | Архивный проект | Баннер «Проект в архиве · только чтение» без кнопки; возврат — в администрировании (функция после релиза) |
| Q-13 | Подписка в архивном проекте | Запрещена |
| Q-15 | Markdown | `ngx-markdown` со встроенным санитайзером; очистку проверить на описании и комментариях |
| Q-16 | Первая смена пароля | Маршрут `/change-password` и гвард для `mustChangePassword` |
| Q-17 | «Обновил …» и счётчики вкладок | `commentCount` в задаче; «обновлено N назад» без имени |
| Q-18 | Шаблон Dev team | Первая доска — «Разработка»; статус Plan — категории `todo` |
| Q-20 | Спорные правила интерфейса | Формы правки: «Сохранить» неактивна до изменений; подтверждение для всех удалений; отдельный «опасный» вид кнопки; схема «Остаться / Закрыть без сохранения»; кадры загрузки, пусто и «ничего не найдено» на каждой странице; буква приоритета тёмная на цветном фоне |
| Q-21 | Язык интерфейса | Типы, приоритеты и роли — по-английски как имена собственные; во фразах — по-русски; связи — «Блокирует / Заблокирована»; «Восстановить», «Активировать»; «системный администратор» |
| Q-22 | Тексты уведомлений | Нейтральная форма с автором в конце: «Вас назначили исполнителем · Иван П.» |
| Q-25 | Деактивированные пользователи | Фильтра нет; показываются серым с подписью «(деактивирован)»; поиск кандидатов в участники — от 2 символов |
| Q-26 | Чужие комментарии | Admin и owner могут только удалить чужой комментарий; править — только автор |
| Q-32 | `active` у приглашённого участника | `active = статус ≠ деактивирован`: приглашённый выглядит как обычный участник |
| Q-33 | Уведомление о смене ревьюера | Добавлено (`reviewer_changed`); смена приоритета, срока и прочих полей не уведомляет |
| Q-44 | Повторные уведомления об одном действии | Одно действие — одно уведомление получателю: упоминание > назначение > остальное |
