# Настройки проекта

Связан с [01-scope.md](01-scope.md), [02-scenarios-and-permissions.md](02-scenarios-and-permissions.md), [07-boards-page.md](07-boards-page.md). Макеты: [wireframes/settings/](wireframes/settings/) (`general.svg`, `dictionaries.svg`); макеты `statuses.svg` и `boards.svg` (после релиза) лежат в [archive/wireframes-after-release/](archive/wireframes-after-release/). Страница «Участники» проектируется отдельно.

## 1. Назначение и доступ
Одна страница с левым меню разделов: Общие, Направления, Теги. Разделы «Статусы» и «Доски» — после релиза (Q-05): в первой версии статусы и доски создаёт шаблон проекта. Здесь owner и admin настраивают проект.
- Маршрут: `/p/PROJ/settings/:section` (`general`, `subsystems`, `tags`); открывается из меню проекта (⚙) → «Настройки проекта».
- Видят пункт меню и страницу только owner и admin. Member и viewer пункта не видят; по прямой ссылке показывается «Нет доступа».
- Ключи по разделам: Общие — `project-update` (название, описание); Направления — `subsystem-manage`; Теги — `tag-manage`. Для разделов после релиза остаются ключи `status-manage` (Статусы) и `board-manage` (Доски).

## 2. Общие правила разделов
- Списки редактируются через окна (диалоги); одно окно служит и для создания, и для правки. Исключение — направления: создаются полем «Новое направление» и кнопкой «Добавить» над таблицей, правятся окном.
- Каждое изменение сохраняется сразу после подтверждения в окне; общих кнопок «Сохранить» нет (кроме раздела «Общие»).
- Названия уникальны внутри своего списка без учёта регистра; при повторе под полем показывается «Такое название уже есть».
- Ошибки сети и сервера показываются общим сообщением приложения.

## 3. Разделы
### Общие
- Поля: название (обязательно), ключ (только чтение, задаётся при создании проекта), описание.
- «Сохранить» неактивна, пока нет изменений, и становится активной при первой правке (исключение для форм правки, [12](12-ui-rules.md), раздел 2).
- «Опасной зоны» нет: сменить owner может только системный администратор ([10](10-account-and-admin.md), «Проекты»); архивация проекта и восстановление из архива — после релиза (Q-23). Когда архивация появится, настройки архивного проекта видит только owner ([12](12-ui-rules.md), раздел 3).

### Статусы (после релиза)
- **В первой версии не делается** (Q-05). Ручки бэкенда ([b03](backend/03-dictionaries-and-templates.md)) остаются в контракте, интерфейса нет. Описание ниже сохранено для возврата; сортировку статусов тогда делаем кнопками ↑/↓ с тем же `PUT .../statuses/order`, а не вторым drag&drop (E-21).
- Таблица статусов в порядке workflow: ручка перетаскивания, цвет, название, категория, переключатель «Причина при переводе», кнопки правки и удаления. Порядок меняется перетаскиванием строк и определяет порядок статусов в списках выбора.
- Поля статуса: название (обязательно), цвет (один из 8 фиксированных), категория (Backlog / To do / In progress / Done), флаг `requiresReason` (причина обязательна при переводе в статус; по умолчанию включён у Cancelled и Blocked шаблонов).
- Категория определяет поведение: задачи в статусе категории Done считаются закрытыми (проставляется дата закрытия, действует окно Done на досках, срок не краснеет).
- **Удаление:**
  - Статус без задач и без досок удаляется после подтверждения.
  - Если в статусе есть задачи, обязательно выбрать статус, в который их перенести; перенос происходит при удалении.
  - Если статус используется колонкой досок, окно перечисляет доски и предупреждает, что колонка будет убрана. Если статус — единственная колонка какой-либо доски, удалить его нельзя (сначала изменить или удалить доску).
  - Единственный статус категории Done удалить нельзя.
- Переименование и смена цвета применяются сразу везде.

### Доски (после релиза)
- **В первой версии не делается** (Q-05). Доски и их фильтры («Frontend», «Backend») создают шаблон проекта и ментор.
- Список: название, колонки (кратко цепочкой), базовый фильтр; кнопки правки и удаления. Порядок досок в переключателе видов — по дате создания.
- Окно доски: название (обязательно), колонки (список статусов: добавить из ещё не использованных, убрать, перетащить для порядка; минимум одна колонка, статус в колонках не повторяется), базовый фильтр (Исполнитель, Ревьюер, Приоритет, Тип, Направление, Теги; без статуса), окно Done в днях (показывается, если среди колонок есть статус категории Done; число от 1 до 365, по умолчанию 14).
- Удаление доски: подтверждение; задачи не удаляются. Последнюю доску проекта удалить нельзя.
- Изменение колонок и фильтра применяется к доске сразу.

### Направления
- Таблица: название, число задач; поле «Новое направление» и кнопка «Добавить» над таблицей; правка названия в окне; удаление.
- У направления нет цвета и других свойств.
- Удаление направления с задачами: окно просит выбрать, куда перенести задачи, в списке есть вариант «Без направления».

### Теги
- Таблица: тег, число задач, поиск по названию. Теги создаются в задаче; здесь можно переименовать (уникальность без учёта регистра) и удалить. Список тегов грузится целиком, без пагинации; поиск и подпись «Показано N из M» под таблицей — клиентские, по уже загруженному списку. Серверный параметр `search` нужен только выпадающему «+ Тег» в задаче.
- Удаление: подтверждение «Тег будет убран у N задач», сами задачи остаются. Переноса нет.

## 4. Состояния
У каждого раздела три состояния с отдельными кадрами ([12](12-ui-rules.md), раздел 3):
- **Общие:** загрузка (индикатор вместо формы); «Сохранить» неактивна, пока нет изменений (исключение для форм правки); ошибка сохранения — общее сообщение приложения, введённые значения остаются.
- **Направления:** загрузка таблицы (индикатор); пусто («Направлений пока нет», подсказка «Добавьте первое направление»); «Добавить» с пустым полем — ошибка «Введите название» под полем, с повтором — «Такое название уже есть».
- **Теги:** загрузка таблицы; пусто без поиска («Тегов пока нет», подсказка «Теги создаются в задачах»); поиск ничего не нашёл («Ничего не найдено» и «Сбросить»); переименование в уже существующее название — «Такое название уже есть» под полем окна.
- **Для всех разделов:** нет доступа (member, viewer, «Нет доступа»); ошибки сети и сервера — общее сообщение приложения с «Повторить».
- **Удаление** направления и тега — окно подтверждения с последствиями (раздел 3). **Статус в досках** (после релиза): статус, который используется колонкой, удаляется после окна со списком досок; единственная колонка доски — удаление статуса запрещено (описано в «Статусы» выше).
Окна и ошибки валидации — как на макетах.

## 6. API
Группы OpenAPI: Projects, Statuses, Boards, Subsystems, Tags. Контракт — [backend/openapi/openapi.yaml](backend/openapi/openapi.yaml); ТЗ — [backend/02-projects-members-permissions.md](backend/02-projects-members-permissions.md), [backend/03-dictionaries-and-templates.md](backend/03-dictionaries-and-templates.md).
- Список статусов приходит с числом задач и списком досок, где статус используется; направления и теги — с числом задач.
- Удаление статуса и направления с задачами требует переназначения: параметр `moveTo` (для направления допустимо `none`).
- После релиза: порядок статусов сохраняется одним запросом `PUT /projects/:projectId/statuses/order` со списком идентификаторов.

## 7. Сценарии
Продолжают P3–P7 документа 02.
- **S1 Изменить название и описание проекта.**
- **S2–S6 (после релиза):** добавить, изменить и упорядочить статусы, удалить статус (без задач, с переносом, используется досками, единственный Done); создать, изменить и удалить доску.
- **S7 Добавить, переименовать и удалить направление** (с переносом задач).
- **S8 Переименовать и удалить тег.**
- **S9 Роль admin и owner:** все разделы. **Member и viewer:** нет доступа. (Смена владельца — только в администрировании, сценарий A14 документа 10.)

## 8. Оценка трудозатрат фронта: ≈ 34 ч
Каркас страницы, меню разделов, маршруты и права 6; Общие (форма) 8; Направления 8; Теги 8; состояния и права 4. Окна создания, правки и удаления с переносом одинаковые, на них стоит сделать общие компоненты.

**Решено (Q-05):** разделы «Статусы» (таблица с перетаскиванием 10, окно 8, удаление с переносом 6 — 24 ч) и «Доски» (список 4, окно с колонками и фильтром 14, удаление 2 — 20 ч), всего ≈ 44 ч, — после релиза и в сумму не входят. До этого шаблоны «Dev team» и «Simple» создают статусы и доски на бэкенде, доски по направлениям добавляет ментор. Доступ и API разделов остаются теми же.

## 9. Открытые вопросы
Открытых вопросов нет. Решено: дата закрытия при смене категории статуса не пересчитывается; пределов на число статусов, досок, направлений и тегов нет; список тегов без пагинации (с поиском).

## Приёмка
Формат и сид — как в [04](04-task-card.md), раздел «Приёмка»; справочники — [backend/03](backend/03-dictionaries-and-templates.md), §8. Роль с правом: `anna_owner` (owner), `boris_admin` (admin); `eva_viewer` — viewer. Для member проверяется `clara_member`. S2–S6 (статусы и доски) — после релиза, пунктов нет.

**S1 Название и описание**
- S1.1 Дано: `anna_owner`, `/p/DEMO/settings/general`. Действие: изменить название и описание. Ожидаю: «Сохранить» неактивна без изменений; после сохранения новое название в переключателе проектов и после обновления; ключ только чтение.
- S1.2 Дано: пустое название. Ожидаю: ошибка под полем, сохранение не проходит.
- S1.3 Дано: `boris_admin`. Ожидаю: то же, что у owner; «опасной зоны» нет.

**S7 Направления**
- S7.1 Дано: `boris_admin`, «Направления». Действие: добавить через поле «Новое направление». Ожидаю: в таблице появилось с числом задач.
- S7.2 Дано: название, уже существующее в другом регистре. Ожидаю: «Такое название уже есть».
- S7.3 Дано: направление. Действие: переименовать через окно. Ожидаю: новое имя видно в фильтрах и карточках.
- S7.4 Дано: направление с задачами. Действие: удалить. Ожидаю: окно просит выбрать, куда перенести, есть «Без направления»; после подтверждения задачи перенесены.
- S7.5 Дано: пустой список. Ожидаю: «Направлений пока нет» и подсказка; при загрузке — индикатор. «Добавить» с пустым полем: кнопка активна, под полем «Введите название».

**S8 Теги**
- S8.1 Дано: `anna_owner`, «Теги». Действие: поиск по названию. Ожидаю: фильтрация на клиенте, подпись «Показано N из M»; нет совпадений — «Ничего не найдено» и «Сбросить»; в проекте без тегов — «Тегов пока нет».
- S8.2 Дано: тег `ux`. Действие: переименовать на существующее имя. Ожидаю: «Такое название уже есть»; на новое — переименован в задачах.
- S8.3 Дано: тег с задачами. Действие: удалить. Ожидаю: подтверждение «Тег будет убран у N задач»; тег убран, задачи на месте.

**S9 Роли**
- S9.1 Дано: `anna_owner` и `boris_admin`. Ожидаю: пункт «Настройки проекта» и все три раздела доступны.
- S9.2 Дано: `clara_member` и `eva_viewer`. Ожидаю: пункта в меню ⚙ нет; прямая ссылка `/p/DEMO/settings/general` показывает «Нет доступа».
- S9.3 Дано: любая роль, остановлен бэкенд. Ожидаю: индикатор загрузки раздела, затем общее сообщение приложения.
