# Сценарии и роли (черновик v1)

Связан с [01-scope.md](01-scope.md). Сценарии подтверждены как черновик: без макетов их трудно проверить, они будут уточняться при проработке страниц.

## 1. Роли
- **Системный администратор** (глобальная роль): приглашает людей, деактивирует их, создаёт проекты, назначает и меняет owner. Содержимое проектов видит только как участник.
- **В проекте:** owner, admin, member, viewer. У одного пользователя могут быть разные роли в разных проектах. Системный администратор внутри проекта действует по своей проектной роли.

## 2. Права
Ключи и матрица «роль → ключ» (глобальные, проектные, «своё», ограничения admin) описаны только в [13-data-model-and-permissions.md](13-data-model-and-permissions.md), §4; соответствие ключей ручкам — в §5 того же документа (генерируется из OpenAPI). Здесь ключи названы только в сценариях.

**Личные действия** (любой пользователь, ключи не нужны): профиль, смена пароля, привязка Telegram, уведомления.

## 3. Правила и исключения
1. В проекте всегда минимум один owner; последнего owner нельзя удалить, понизить или деактивировать (сначала передать).
2. — удалён, номер не переиспользуется. Правило «своё» (кто может править и удалять чужое, какое поле сравнивается с `userId`) описано в 13 §4, «Как работает «своё»».
3. — удалён (архивация проекта — после релиза, Q-23), номер не переиспользуется.
4. Архивная задача скрыта на досках и в списках; admin/owner видят её через пункт «Архивные» в фильтре статуса и могут восстановить. Архивация задачи с подзадачами архивирует и все её подзадачи (после подтверждения), восстановление родителя возвращает все его подзадачи.
5. Статус и направление нельзя удалить, пока они используются: сначала переназначение. В workflow всегда есть хотя бы один статус категории done.
6. Деактивированный пользователь теряет вход; его комментарии и история остаются; как исполнитель/ревьюер показывается серым с подписью «(деактивирован)». Отдельного фильтра «назначено деактивированным» нет.
7. Удаление участника из проекта снимает его с исполнителя и ревьюера задач проекта, запись попадает в историю.
8. Права отдаются через `GET /projects/:id/me` при входе в проект и после любого 403; фронт скрывает недоступные действия.
9. Viewer видит доску без возможности перетаскивать; «Списать время» ему не показывается, комментарии доступны.

## 4. Сценарии
Формат: **ID название** — предусловие → шаги → результат. *Права:* ключи. *Ошибки:* ключевые отказы.

### Системный администратор
Сценарии SA1–SA6 и U1–U8 подробно описаны как A1–A14 в [10-account-and-admin.md](10-account-and-admin.md).
- **SA1 Первый запуск.** Сид-аккаунт системного администратора создаётся миграцией; при первом входе обязательна смена пароля. *Права:* —. *Ошибки:* слабый пароль.
- **SA2 Пригласить пользователя.** Админка → «Пригласить» → имя → ссылка (одноразовая, срок 7 дней) → скопировать и передать. Результат: пользователь в статусе «приглашён». *Права:* `user-invite`.
- **SA3 Повторная ссылка.** Список пользователей → «Выдать новую ссылку» → старая ссылка и пароль/привязка Telegram сбрасываются. *Права:* `user-reissue-access`.
- **SA4 Деактивировать / активировать.** Список → «Деактивировать» → вход закрыт, сессии отозваны. *Права:* `user-deactivate`. *Ошибки:* пользователь — последний owner проекта (сначала передать).
- **SA5 Создать проект.** Админка → «Новый проект» → название, ключ (`PROJ`, уникальный), шаблон, owner → проект с доской(ами) по шаблону. *Права:* `project-create`. *Ошибки:* занятый ключ.
- **SA6 Сменить владельца.** Проект → «Сменить владельца» → выбрать участника. *Права:* `project-change-owner`. *Ошибки:* выбранный не участник проекта.

### Любой пользователь
- **U1 Принять приглашение.** Открыть ссылку → выбрать «Пароль» (логин, пароль и повтор) или «Через Telegram» (подтвердить в боте, логин предлагается из Telegram) → вход в систему. *Ошибки:* ссылка использована или истекла.
- **U2 Вход по паролю.** Форма (`username`, пароль) → переход в последний проект. *Ошибки:* неверные данные, пользователь деактивирован.
- **U3 Вход через Telegram.** Кнопка → открывается бот по `deepLink` → в боте «Да, это я» (вход засчитывается только по нажатию кнопки; «Это не я» отменяет запрос) → вкладка сайта по опросу статуса получает сессию (waiting → confirmed / expired). *Ошибки:* токен истёк (по умолчанию 5 минут), Telegram не привязан к аккаунту.
- **U4 Привязать второй способ.** Профиль → «Привязать Telegram» (deepLink) или «Установить пароль». *Ошибки:* Telegram уже привязан к другому аккаунту.
- **U5 Сменить пароль.** Профиль → старый и новый пароль.
- **U6 Нет проектов.** После входа без членств показывается экран «Вас ещё не добавили в проекты».
- **U7 Переключить проект.** Шапка → выбор проекта → последняя доска проекта.
- **U8 Уведомления.** Колокольчик со счётчиком (polling) → список → клик ведёт к задаче и отмечает прочитанным; те же события — в Telegram-бот.

### Owner / admin
Сценарии P1–P2 (участники) подробно описаны как MB1–MB6 в [09-members-page.md](09-members-page.md); P3–P6 (статусы, доски, справочники, теги) — как S1–S9 (статусы и доски — после релиза) в [08-project-settings-page.md](08-project-settings-page.md).
- **P1 Добавить участника.** Участники → «Добавить» → поиск среди пользователей системы → роль. *Права:* `member-add`. *Ошибки:* уже участник.
- **P2 Сменить роль / удалить участника.** Участники → меню строки. *Права:* `member-role-change`, `member-remove`. *Ошибки:* последний owner; попытка изменить owner.
- **P3 Настроить статусы** (после релиза). Настройки → «Статусы» → добавить, переименовать, цвет, категория, порядок, `requiresReason`, удалить (с переназначением). *Права:* `status-manage`. *Ошибки:* удаляется последний done.
- **P4 Создать доску** (после релиза). Настройки → «Доски» → название, фильтр (чипы), колонки (выбор статусов, порядок), окно Done (N дней). *Права:* `board-manage`. *Ошибки:* удаление последней доски.
- **P5 Справочники.** Настройки → направления (CRUD, переназначение при удалении). *Права:* `subsystem-manage`.
- **P6 Теги.** Настройки → теги: переименовать, удалить (убирается у задач). *Права:* `tag-manage`.
- **P7 Передать owner.** Только системный администратор, в администрировании (SA6); в настройках проекта этого действия нет. Архивации проекта в первой версии нет.
- **P8 Восстановить задачу.** Список → фильтр статуса → «Архивные» → открыть задачу → «Восстановить». *Права:* `task-restore`.
- **P9 Модерировать комментарий.** В карточке удалить чужой комментарий; править чужой нельзя, правит только автор. *Права:* `comment-delete` (админ — любой).

### Member
- **M1 Открыть доску.** Подробно: [07-boards-page.md](07-boards-page.md). Переключатель видов → фильтры → Исполнитель или Ревьюер = «Я». *Права:* `board-view`.
- **M2** — удалён, номер не переиспользуется.
- **M3 Полное создание.** Подробно: [05-create-task-dialog.md](05-create-task-dialog.md). Кнопка «+ Задача» → форма (название, описание, type, поля; для подзадачи — родитель). *Ошибки:* подзадача под подзадачей.
- **M4 Перенос карточки.** (см. B4–B5 в [07-boards-page.md](07-boards-page.md)) DnD в другую колонку → статус меняется → при `requiresReason` (на доске это Blocked; Cancelled ставится в карточке) открывается диалог причины (отмена возвращает карточку). *Права:* `task-move`. *Ошибки:* сбой запроса — откат и общее сообщение приложения ([12-ui-rules.md](12-ui-rules.md), «Язык и термины»).
- **M5 Карточка.** Клик → боковая панель (адрес вида получает `?task=PROJ-123`; входная ссылка `/p/PROJ/tasks/PROJ-123` ведёт на вид с этим параметром); поля панели сохраняются автоматически. *Права:* `task-update`.
- **M6 Описание.** Редактор markdown + превью, явная кнопка «Сохранить».
- **M7 Комментарий и ответ.** Вкладка «Комментарии» → текст (markdown) → «Ответить» вставляет `@username` → упомянутому уходит уведомление. *Права:* `comment-create`.
- **M8 Списать время.** «Списать время» → `2h 30m`, дата (по умолчанию сегодня), комментарий (необязателен). *Права:* `worklog-create`. *Ошибки:* неверный формат.
- **M9 Связи и ссылки.** Блок «Связи» → добавить связи «Блокирует» / «Заблокирована» (задача того же проекта); блок «Ссылки» → URL с названием. *Права:* `link-manage`. *Ошибки:* связь задачи с самой собой, циклическая blocks.
- **M10** — удалён (вложения — после релиза, Q-05), номер не переиспользуется.
- **M11 Подписка.** Звёздочка в шапке карточки. *Права:* `watch-toggle`.
- **M12 Планирование.** Доска «Планирование»: перетаскивание Backlog → PBR → Plan → To do; после переноса в To do карточка видна на доске разработки. *Права:* `task-move`.
- **M13 Ревью.** Назначить ревьюера → перенести в In review → ревьюер комментирует и переводит в In test или в Reopened (комментарий необязателен). *Права:* `task-update`, `task-move`, `comment-create`.
- **M14 Архивировать свою задачу.** Меню карточки → «Архивировать» (только если `reporter` = я). *Права:* `task-archive`.
- **M15 Список.** Сценарии страницы «Все задачи» (L1–L10: поиск, фильтры, сортировка, пагинация, раскрытие подзадач) описаны в [06-all-tasks-page.md](06-all-tasks-page.md).

### Viewer
- **V1 Просмотр.** Доски, список, карточка в режиме чтения (без DnD и полей редактирования).
- **V2 Комментарий.** Оставить и править/удалять свой комментарий. *Права:* `comment-create`, `comment-update`, `comment-delete` (своё).
- **V3 Подписка.** Звёздочка. *Права:* `watch-toggle`.

## 5. Граничные случаи
- Два пользователя двигают одну карточку: побеждает последний, polling обновляет доску; при перетаскивании polling приостанавливается.
- Правка поля, изменённого другим: field-level last-write-wins, карточка обновляется по ответу сервера.
- Потеря прав в середине сессии: 403 → общее сообщение приложения, перезапрос `/projects/:id/me`, перерисовка интерфейса. Если человека удалили из проекта, `GET /projects/:id/me` и любой запрос проекта отвечают 404: экран «Нет доступа к проекту» и переход к списку проектов; несохранённый текст остаётся на экране для копирования. Общая таблица реакций на ответы API — [12](12-ui-rules.md), раздел 8.
- Истёкшая ссылка приглашения; истёкший токен Telegram-входа.
- Понижение роли при открытой панели карточки.
- Drop в статус с `requiresReason` и отмена диалога.
- Задача с незакрытыми «blocked by» переведена в Done: разрешено, бейдж «заблокировано» остаётся до закрытия блокирующих.
- Удаление статуса или направления с задачами: сначала переназначение.
- Owner деактивирован: запрещено, пока не передан.
- Пустой проект без досок: шаблон создаёт доски; удалить последнюю доску нельзя.

## 6. Открытые вопросы
Открытых вопросов нет. Решено: приглашение действует 7 дней, токен Telegram-входа 5 минут, пароль не короче 8 символов с буквой и цифрой, «blocked by» + Done разрешено (бейдж остаётся).
