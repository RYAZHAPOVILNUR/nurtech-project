# Инструкция для ИИ-агента разработчика бэкенда

Ты помогаешь разработчику бэкенда реализовать API учебного таск-менеджера по готовому ТЗ. Фронтенд (Angular + Taiga UI) пишут ученики ментора; бэкенд — зона твоего разработчика.

## Первый шаг: расскажи о проекте
Прежде чем писать код, прочитай документы из раздела «Источники» и коротко расскажи разработчику:
1. **Что за продукт.** Таск-менеджер: доски с колонками-статусами и drag&drop, карточка задачи (поля, подзадачи, связи, ссылки, комментарии, учёт времени, история), роли в проекте.
2. **Чем MVP отличается от полной версии — это главное.**
   - `docs-short/` — **MVP, который делаем сейчас**: доска, карточка задачи, создание задачи, вход по паролю и профиль. 35 ручек, 4 пакета ТЗ.
   - `docs/` — **полная версия на будущее**: Telegram, уведомления, подписки, администрирование, участники, настройки проекта, список «Все задачи», архивация. Сейчас её **не реализуем**. Контракт MVP — подмножество полного: те же пути и имена полей, лишнее убрано (отличия — в `docs-short/backend/openapi/CHANGELOG.md`).
3. **Что требуется от бэкенда:** пакеты ТЗ и их сроки, служебные команды (пользователи, ссылки-приглашения, проекты, участники, доски-фильтры — администрирования в интерфейсе нет), тестовые данные `DEV_SEED`, стенд с фронтом и `/api` на одном адресе.
4. **Открытые вопросы**, если при чтении нашёл противоречия между ТЗ и контрактом.

После рассказа жди указаний разработчика: с чего начать, какой стек, что делать дальше.

## Правила работы
- Ответы строго по `openapi.yaml`. Контракт не меняй сам: если он кажется неверным или противоречит ТЗ — остановись, опиши проблему и предложи правку. Изменение контракта — это PR в `openapi.yaml` с повышением `info.version` и строкой в `CHANGELOG.md`, после согласования с ментором.
- Обязательны только контракт и наблюдаемое поведение. Технологии, СУБД, схему хранения и алгоритмы выбирает разработчик; разделы «Рекомендации (необязательно)» — подсказки, а не требования.
- Пакеты делаются по одному, по порядку. Для каждого: реализация, служебные команды и данные `DEV_SEED` из раздела «Тестовые данные», затем самопроверка по разделу «Критерии приёмки» через HTTP-запросы. В конце пакета — список пунктов приёмки с результатом.
- `error.message` — по-русски и понятен пользователю: фронт показывает его как есть, особенно у ответов 409.
- Не добавляй ручки, поля и функции «на будущее» из полной версии.
